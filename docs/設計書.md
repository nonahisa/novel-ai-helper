## 0. この文書について

- ヘルパー（Chrome 拡張、Manifest V3）の設計の正はこの文書。2026-10-12 に、統合小説執筆環境（VS Code 拡張 novel-ai-assistant）の設計書 6.79 節とその周り（6.3.6.1 公募の一覧・6.66.6 章立て）から、ヘルパーの側の中身を移して独立させた
- **ヘルパーは独立した製品である。** 統合小説執筆環境は、ヘルパーが渡すデータの**いまの受け手の1つ**で、ヘルパーの一部ではない。受け手の側（受け口・取り込み・台帳・グラフ・助言）の設計は、受け手それぞれの文書にある（統合小説執筆環境なら、その設計書 6.79 節）
- 受け手と取り交わすもの（封筒の形・合図・お互いに守ること）は [4章](#4-受け手との約束) にまとめる。受け手を足すときに読むのはこの章
- 使い方と画面の文言は `README.md`、ストアの申告は `store/` と `PRIVACY.md` が正。この文書は「何を決めたか・なぜか」を書く
- 書き方：決めたこと／なぜ（1〜3行）／測った数字（日付つき）／守る決まりだけを書く。経緯は `docs/進捗と引継ぎ.md` の作業の記録へ

## 1. 何をする道具か

作者が**自分で開いたページの中だけ**で動き、次の4つをする。

| 働き | 向き | 起点 |
|---|---|---|
| **貼り込み**：受け手がコピーした原稿を、投稿サイトの話の作成画面の題と本文の欄へ入れる | 受け手 → ヘルパー → ページの欄 | アイコンを押す／右クリック「本文を貼り込み」 |
| **読者の反応の読み取り**：作者自身の作品の管理画面（と Narou.fun の作品ページ）に出ている数を読み、拡張の中に記録し、受け手へ渡す | ページ → ヘルパー → 受け手 | 開いたとき（覚えた作品だけ）＋押したとき |
| **公募の一覧の読み取り**：公募の一覧のページに並ぶ募集を読んで受け手へ渡す | ページ → ヘルパー → 受け手 | 押したとき |
| **章立ての読み取り**：カクヨムの作品管理の画面から大見出しと話の並びを読んで受け手へ渡す | ページ → ヘルパー → 受け手 | 右クリック「章立てを取得」 |
| **ランキングのお祝いと順位**（0.19.0）：カクヨム・アルファポリスのランキングの画面に覚えた作品が載っていたら吹き出しでお祝いし、順位を記録して受け手へ渡す | ページ → ヘルパー → 受け手 | 開いたとき（承認した種類だけ）＋押したとき |

**受け手が無くても使える**（0.10.0）：読者の反応を拡張の中に記録し、作品ごとにいまの数・日ごとの推移・3つの率を説明のページで集計する（[7.6](#76-記録と簡易集計0100)）。受け手へ渡すかどうかは、説明のページの「統合小説執筆環境へ渡す」の入・切で決める（新しく入れたときは切、0.10.0 以前から更新したときは入。0.11.0）。切っているときは、溜まり（受け手へ渡す分）に溜めず、VS Code も呼ばない。貼り込みは入・切にかかわらず働く（0.11.1）。

## 2. 越えない一線

統合小説執筆環境の「サイトへ HTTP を1行も書かない」と同じ考え方。**約束ではなくコードで守る**——`test/redLine.test.js` がフォルダーを辿ってプログラムの中身を走査し、毎回確かめる。

1. **通信を1本もしない**（`fetch`・`XMLHttpRequest`・`WebSocket`・ビーコンを書かない）。動くのは作者が自分で開いたページの中だけ。保存は `chrome.storage.local` だけで、`chrome.storage.sync`（Google アカウントで同期＝送ることになる）は使わない。外の字体・ライブラリも読み込まない
2. **送信ボタンを押さない。** クリック・送信を起こすコードを持たない。欄を埋めたところで終わり、確かめて投稿するのは作者（なろう第14条23号が明確に禁じるのは自動投稿）
3. **認証情報に触れない。** パスワード欄のあるページでは欄を探す前に降りる。Cookie・セッションを読み書きしない
4. **ページから集めない。** 読むのは、貼り込みでは「埋める欄が在るか・空か」と、アルファポリスの章の選択肢の字（封筒の章と比べるためだけ。外へ持ち出さない。0.15.0）だけ。読み取りでは、作者自身の管理画面（0.17.0 からアルファポリスの /mypage/ の3画面も。設定の画面ではタグの欄の値と連載の状態の選ばれた選択肢を**読むだけ**で、書き換えない）と、作者が覚えた作品の Narou.fun のページに出ている「ラベルと数の組」・作品名・タグと連載の状態の短い字（0.16.0）・公募の枠の文・章立ての字と、ランキングの画面の**覚えた作品の行の**順位と作品名（0.19.0。ほかの行は作品へのリンクの行き先を照合に見るだけ。[7.8](#78-ランキングの画面とお祝い0190)）だけ。本文・他人の作品・ページ全体の文字は読まない（読む文字には長さの上限を掛ける）
5. **作者の操作が起点。** 貼り込み・公募・章立ては押したときに1回だけ。**開いただけで読むのは、覚えた作品の読者の反応の画面だけ**（0.9.0。0.14.0 からは作者が承認したページの種類だけ。0.19.0 のランキングの画面も同じで、覚えた作品の行だけ）で、開いてから少し待って1回だけ読む。ページを見張る仕組み（MutationObserver・setInterval）を持たない。次のページへ自動で進まない
6. **ページの中に表示や部品を差し込まない**（0.8.0）。結果は Chrome のお知らせで出す
7. **勝手に新しいタブや窓を開かない**（0.8.0）。開くのは、入れた直後の説明のページ（1回）と、作者が選んだときの説明のページ・説明のページの中のリンクだけ。受け手を呼ぶときもいまのタブのまま（[4.3](#43-起こす合図)）

番人のテストが見張ること：通信のコードが無い／送信のコードが無い／Cookie に触れない／文字列からコードを作らない（動的コード実行・HTML 注入の禁止パターン17規則）／HTML を組み立てて差し込まない／ページへ要素やコードを差し込まない／ページと窓越しにやり取りしない／新しいタブや窓を開かない／受け手を呼ぶ場所が1つでリンクにデータを載せない／権限が増えていない／外を指すリンクは説明のページの1本だけ。**走査する仕組みそのものが働くか**（新しいファイルを拾うか、禁止の書き方を本当に見つけるか）も、架空のソースを読ませて同時に確かめる。調べるファイルは手書きの一覧でなく、その場でフォルダーを辿って集める（`node_modules`・`test`・`.git` 以外）。

**ページの文字を読んでよいファイルは名指しで決めてある**：数を読む `content/read.js`、欄を埋める `content/fill.js`、公募を読む `content/contestRead.js`（0.12.0）、章立てを読む `content/chapterRead.js`（0.13.0）。受け手へ渡すデータを組み立てるのもこれらと、束で包む `common/stash.js` だけ。**ここへファイルを足すことは「しないこと」を変えることで、ついでに足してよいものではない。**

## 3. 規約の確認結果

2026-09-05 に各サイトの利用規約の原文を確かめた。

| サイト | 該当条文 | 判定 |
|---|---|---|
| 小説家になろう | 第14条23号「なろうデベロッパーで提供しているAPIを利用する以外の方法で、本サービスに自動化された手段を用いてアクセスしたり、データを収集したりすること」を禁止 | 貼り込み（欄を埋めるだけ）は文言上対象外と読めるが、最も厳しい書きぶりで、**送信の自動化は明確に一線を越える**。**貼り込みも読み取りもしない**（表に枠だけ置き `supported: false`）。読み取りは作者の裁定（2026-09-05）で対応しない。なろうデベロッパー API の例外も作らない |
| カクヨム | 第14条（禁止事項27号）に自動化・スクレイピングの明示条文なし。第5条2号「過剰に負荷をかける利用」・14条24号「運営を妨害する行為」のみ | 負荷も妨害も生まない——**貼り込み・読み取りとも可** |
| アルファポリス | 第13条（禁止事項16項）に自動化・収集の明示条文なし | **可**。貼り込みは投稿画面の形を確かめて対応（0.14.2）。読み取りは作者の管理画面（/mypage/ の下）だけ（0.17.0。作者の決定「数も読むようにする」） |
| note | 規約本文のページが機械取得を拒む（403）ため原文未確認 | 人の目で原文を確かめるまで対応しない |
| pixiv小説 | 共通規約第14条24号「機械的にまたは短時間で大量に、フォロー、ブックマーク、コメント、メッセージの送信その他本サービス上の操作を行う行為」を禁止 | **グレー**。対応するかは作者の最終判断 |
| ハーメルン | 禁止事項に「サイトに過度の負荷をかける行為（F5キー連打 活動報告を利用したチャット ツール使用など）」 | **グレー**（「ツール」の語が明示される唯一のサイト）。対応するかは作者の最終判断 |
| Narou.fun（`db.narou.fun`、なろうの分析サイト。2026-11-01 のリニューアルで名は「なろうファンDB」） | 2026-09-23 に確認。robots.txt は全許可（`Disallow:` が空）。利用規約のページは見つからない。サイト自身に「クリップボードにコピー」のボタンがある | なろう本体とは別のサイトとして、**作者が覚えた作品のページだけ読む**（0.6.0）。そこからの「解析」の行き先（KASASAGI、なろうの運営会社のアクセス解析）はなろう本体と同じ扱いで読まない |
| ノベルポータル（`creative-story.net`） | 2026-09-23 に確認。利用規約のページは無く、プライバシーポリシーに「掲載している文章や画像の無断転載を禁止」 | 作者が開いたページの公募を作者の手元の受け手へ移すだけで、載せ直さない——転載に当たらない |
| ツクリテミライ（`tsukuritemirai.com`） | 2026-09-23 に確認。利用規約のページは見つからない。免責に「掲載情報の正確性を保証しない。応募の前に主催者の公式情報を確かめる」 | 読む。受け手の側でも同じ但し書きを添える |

## 4. 受け手との約束

ヘルパーは、**データを受け取って使うアプリ（受け手）**とクリップボード越しにやり取りする。この章は、受け手が誰であっても変わらない取り決めを書く。封筒の形を変えるときは、この章と、受け手それぞれの読み口を同時に直す。

### 4.1 いまの受け手

| 受け手 | 種類 | 起こす合図 | 受ける封筒 | 渡す封筒 |
|---|---|---|---|---|
| **統合小説執筆環境**（VS Code 拡張、拡張ID `nonahisa.novel-ai-assistant`） | 手元のアプリ | `vscode://nonahisa.novel-ai-assistant/<パス>` | `novelai-stats`／`novelai-stats-bundle`／`novelai-contests`／`novelai-chapters` | `novelai-post` |

**いまの受け手は統合小説執筆環境だけ**。ヘルパーの文言（「統合小説執筆環境へ渡す」など）と、起こす合図の3つの定数（`common/actions.js` の `VSCODE_IMPORT_URL`・`VSCODE_CONTESTS_URL`・`VSCODE_CHAPTERS_URL`）は、この1つの受け手を前提に書いてある。受け手を足すときは [4.12](#412-受け手を足すとき決めること) を決めてから直す。

### 4.2 経路はクリップボードだけ

- データは**クリップボードに置いた JSON（封筒）**だけで渡す。受け手との間に通信・ネイティブメッセージング・ローカルのサーバー・ファイルの受け渡しを作らない（常駐が増え、構成が重くなる。クリップボードで足りる）
- クリップボードの読み書きは、押したときだけ開く画面に出ない拡張のページ（`offscreen.html`）で行う（0.8.0。ポップアップを無くしたため）
- **クリップボードは作者の私物**。ヘルパーは自分の封筒の目印が無いものは読んでも使わず、どこにも残さない。受け手にも同じことを求める（[4.10](#410-受け手が守ること)）
- **クリップボードの注意**：Windows の「クリップボードの履歴」「デバイス間の同期」が入っていると、コピーした本文が Microsoft のクラウドを経由しうる。受け手の「変換してコピー」でも同じで、投稿直前の本文なので危険度は低いが、取りやめる未公開の本文も通りうる——README に書いて作者に知らせる

### 4.3 起こす合図

- 読み取りの封筒をクリップボードへ置いたあと、**いまのタブを受け手の合図のリンクへ向ける**（`chrome.tabs.update`）。統合小説執筆環境なら `vscode://nonahisa.novel-ai-assistant/<パス>`
  - `vscode://` のように Chrome が自分では開かない種類のリンクは、Chrome が手元のアプリへ渡すだけで、タブの中のページは入れ替わらない。新しいタブも窓も開かない
  - 画面に出ない拡張のページからは開けない（Chrome は、作者の操作の流れに無いページから手元のアプリを呼ぶことを断る）
  - 同じタブへ続けて向けても2回目は門前払いにならない（0.13.2 で Chromium の実装を読んで確かめた：外部プロトコルの連打止めは、拡張の API を呼ぶたびに開け直される）
- **合図にデータを載せない**。パスだけで、クエリも付けない。リンクに載せると、ブラウザの履歴や OS のログに数が残り、長さの上限で黙って切れる
- いまのパス：

| パス | 置く封筒 |
|---|---|
| `/import-reader-stats` | `novelai-stats-bundle`（まとめて渡す。0.9.0 から） |
| `/import-contests` | `novelai-contests`（0.12.0） |
| `/import-chapters` | `novelai-chapters`（0.13.0） |

- 呼ぶのは**渡したあとだけ**。投稿画面（書きかけの原稿のあるページ）では呼ばない（そこで押せば貼り込みになり、渡さない）
- **届いたかはヘルパーに分からない**（通信しないので返事が来ない。Chrome の「Visual Studio Code を開きますか」で止まることもある）。だから、知らせに「VS Code が前に出なければ、もう一度押してください」を添え（0.13.2）、渡した束を控えに残して「もう一度渡す」で渡し直せるようにする（[7.5](#75-溜まりと控え090)）。合図が届かなくても、受け手の「貼り付けて取り込む」でクリップボードから取り込める

### 4.4 封筒の共通の決まり

- **目印の欄と版の数**で種類を見分ける（`"novelai-post": 1` のように、目印の欄の値が版。束だけは `kind` と `version`）
- **版は完全一致で読む。** 違えば読まない（知らない版を推し量って読むと、欄の意味が変わっていたときに取り違える）
- **知らない欄は読み飛ばす。** だから**省いてよい欄を足すだけなら版を上げない**（実例：`source`・`readAtBasis`・`updatedAt`・`title`・`tags`・`completion`・`ownedVia`）。読めない欄は「欄なし」と同じに扱う
- **形が変わるとき（必須の欄・欄の意味・単位）だけ版を上げ**、ヘルパーと受け手を同時に出す
- **読めなかった数は 0 にせず欄ごと入れない**（0 と書くと、読めなかったのか本当に0なのか、あとから見分けられない）
- 日時は ISO 8601。`readAt` は**読んだ時刻**で、取り込んだ時刻ではない

### 4.5 原稿の封筒 `novelai-post`（受け手 → ヘルパー）

```json
{ "novelai-post": 1, "site": "kakuyomu", "workId": "16816927859000000000", "title": "第13話 星の落ちる夜", "body": "（変換済みの本文）" }
```

アルファポリス宛てで章を選ぶときは `"chapter": "第一章『白い港』"` を添える（0.15.0）。

| 欄 | 決まり |
|---|---|
| `novelai-post` | 版。1 |
| `site` | `kakuyomu`／`alphapolis`（`narou` は表に枠だけあり、貼り込まない） |
| `workId` | 任意。あれば投稿画面の URL の作品IDと突き合わせる（カクヨムは `/my/works/{作品ID}/…`、アルファポリスは `/mypage/novel/save_episode/{作品ID}` の数字9桁。アルファポリスは 0.14.1 まで形が分からず突き合わせなかった）。表に作品IDの取り出し方が無いサイトでは突き合わせを飛ばし、結果の頭に【…ご自分で確かめてください】と出す（当てずっぽうの照合が「たまたま一致」すると、確かめた顔で別の作品へ入れることになるため） |
| `title` | 空でよい（空なら題の欄に触らない） |

| `chapter` | 任意（0.15.0。省いてよい欄なので版は1のまま）。その話が属する大見出しの題。無い・`null`・空（空白だけ）なら章に触らない。**有るのに文字列でない・200字を超えるときは、`title`・`workId` と同じく封筒ごと断る**（知っている欄の形が崩れているのは受け手の不具合で、黙って読み進めると「章が選ばれない」だけが続いて誰も気づかないため）。いま使うのはアルファポリスだけで、カクヨムでは読み飛ばす（投稿画面に章の欄が無い）。選び方は[6章](#6-貼り込みの決めごと)の9 |

- 記法の変換（ルビ・傍点の書き方）は受け手が済ませてから渡す。ヘルパーは変換しない
- `caption`（前書き）は持たない。足すときは版を上げて両方同時に


| 欄 | 決まり |
|---|---|
| `site` | `kakuyomu`、Narou.fun から読んだときの `narou`、アルファポリスの管理画面から読んだときの `alphapolis`（0.17.0。`source` は付けない——受け手は知らない `source` の封筒を断る） |
| `workId` | URL から読んだ作品ID（Narou.fun は Nコード） |
| `title` | 任意（0.13.3）。画面に出ていた作品名。読めないとき・100字を超えるときは欄ごと無し（途中で切らない）。**受け手は照合に使わない**（作品を決めるのは作品IDだけ） |
| `tags` | 任意（0.16.0。作者の頼み、受け手と取り決め済み）。文字列の配列で画面の並びのまま。前後の空白を除き、空と重複は除く（1つ60字・50個まで。長い字はタグとして読まない）。**読めた画面で、タグが0個と分かったときだけ `[]`**。読めない・その画面にタグの欄が無いとき（カクヨムのアクセス数）は欄ごと無し。カクヨムは作品管理の dt「タグ」の次の dd の `/tags/` へのリンクの字、なろうファンDB は `ul[aria-label="キーワード"]` のリンクの字。日時は同じ封筒の `readAt` |
| `completion` | 任意（0.16.0）。`"ongoing"`（連載中）／`"completed"`（完結）。**字で決める**：先頭が「連載中」→ongoing、「完結」を含む→completed、それ以外（なろうの「短編」・印が無い）は欄ごと無し。カクヨムは作品管理の `span[class*="workStatusLabel"]`（実機は `widget-workStatusLabel-running`「連載中」。完結の印は実機未確認）、なろうファンDB は dt「形式」の dd（「連載中・全219話」） |
| `ownedVia` | 任意（0.16.0）。**束にするときに**、その作品の今の覚えた作品（`ownWorks` の `how`）から付ける：本人しか開けない画面で覚えた→`"owner-page"`、作者が「覚える」と答えた・説明のページで書いた→`"approved"`。覚えた作品でなければ欄ごと無し（溜まりの封筒には入れない）。**approved で覚えた作品でも、本人しか開けない画面（カクヨムの作品管理・アルファポリスの /mypage/）で読めたら owner-page に上げる**（0.17.1。覚えた日は変えない。下げない。説明のページで保存し直しても保つ）。受け手は「作者の管理画面から登録された作品」だけを作品一覧の枠に出すのに使う |
| `readAt` | 読んだ時刻。Narou.fun だけはページの「データ取得」の日付の 0:00（日本時間。0.14.1 までは「最終取得日時」。下の `readAtBasis`） |
| `source` | 任意（0.6.0）。いまは `"narou.fun"` だけ。**無ければ、そのサイトの管理画面そのもの**の意味 |
| `readAtBasis` | 任意（0.7.0）。Narou.fun だけ。`"fetched"`＝サイトが数を取ってきた日時（いまは「データ取得」の日付）を読めた／`"clicked"`＝読めず押した時刻へ落とした |
| `entries[].scope` | `"work"`（作品全体）／`"episode"`（話ごと。`episode` は1以上の整数） |
| `entries[].period`・`periodKey` | 任意。`day`（`2026-09-22`）／`month`（`2026-09`）／`year`／`total`。無ければその時点の値。**週は持たない**（受け手の粒度に無いものを月や日へ寄せると、何の数か分からなくなる） |
| `entries[].updatedAt` | 任意。話の最終更新（時差つき）。受け手の離脱率の「基準の話」の材料 |
| `entries[].metrics` | 0以上の整数。欄の名前は下の表。**例外**：Narou.fun の日ごとの増減の行（`period: "day"`）の `bookmarks`・`narou_ratingPoints` は負になりうる（前の日より減った日） |

**画面の表示と欄の写し**（受け手との取り決め）：

| サイト | 画面の表示 → 欄 |
|---|---|
| カクヨム | フォロワー→`bookmarks`、PV→`pv`、★の数→`points`、レビュー→`reviews`、応援→`likes`、応援コメント→`comments` |
| アルファポリス（0.17.0） | お気に入り数→`bookmarks`、累計ポイント→`points`、話ごとのいいね→`likes`。共通の名前に意味が合わないものは `alphapolis_` で始まる名前（受け手は 0.116.1 までは捨てる。次の版（2026-11-01 に main へ入った c1169f27）から7つとも受け取り、順位の2つは「小さいほど良い」として増減のグラフに載せない）：24時間のポイント→`alphapolis_points24h`、累計の順位→`alphapolis_rankTotal`、24時間の順位→`alphapolis_rank24h`、ハート→`alphapolis_hearts`、話ごとのしおり→`alphapolis_bookmarks`、エール→`alphapolis_yells`、誤字報告→`alphapolis_typoReports`。**どの行にも共通の名前を最低1つ入れる**（共通の名前の無い行が混ざると受け手は封筒ごと断る。持たない行は入れない） |

### 4.7 束 `novelai-stats-bundle`（ヘルパー → 受け手。0.9.0）

```json
{ "kind": "novelai-stats-bundle", "version": 1, "handedAt": "2026-09-23T05:10:00.000Z", "items": [ { "novelai-stats": 1, "…": "…" } ] }
```

- `items` の1件は [4.6](#46-読者の反応の封筒-novelai-statsヘルパー-→-受け手) の封筒そのもの（溜めるための印は入れない）。1件＝1つの作品の1つの画面（アクセス数ならそのページ）。**溜めた順**（古いものが先）。空の束は作らない
- 束には**複数の作品が混ざる**。同じ作品の作品管理とアクセス数が両方入ることもある（話ごとの数が重なる）
- **同じ作品の画面を1件にまとめない**（1件＝1画面のまま）。`tags`・`completion` は読めた画面の件にだけ入る（作品管理の件にはあり、アクセス数の件には無い）。どれを今の値とするかは受け手が `readAt` で決める（0.16.0）。`ownedVia` は束にするときに1件ずつへ添える
- 版が1でなければ受け手は束ごと読まない
- **`rankings`（0.19.0。省いてよい欄・版は上げない）**：束の最上位に、ランキングの画面で読んだ覚えた作品の順位の並び。1件は `{site, workId, title?, board, boardLabel, span, genre?, rank, date, readAt}`（`site` は `kakuyomu`／`alphapolis`。`span` は `daily`・`weekly`・`monthly`・`yearly`・`total`・`24h`・`other`。`date` は日本時間の日付）。同じ順位の見分けは `site`＋`workId`＋`board`＋`date`（後のもので上書き）。圏外は作らない。順位が無ければ欄ごと省く。**`items` も `rankings` も空の束は作らない**（順位だけなら `items: []` の束を渡す）
  - なぜ指標名（`kakuyomu_rankDaily…`）にしないか：古い受け手は、共通の指標が1つも無い行を封筒ごと断る。区分はカクヨムだけで195通りある。順位は作品の数ではない。束の最上位なら古い受け手は黙って捨てる（受け手との取り決め 2026-11-02）

```json
  "items": [ { "name": "第3回 みずうみ文学賞", "url": "https://example.com/…", "section": "2026年10月締切", "text": "（1件の枠の文）" } ] }
```

| 欄 | 決まり |
|---|---|

| `readAt` | 読んだ日時（その土地の時差つき。受け手が「○月○日時点の情報」と出すため） |

### 4.9 章立ての封筒 `novelai-chapters`（ヘルパー → 受け手。0.13.0）

```json
{ "novelai-chapters": 1, "site": "kakuyomu", "workId": "1177354054000000000", "pageUrl": "https://kakuyomu.jp/my/works/1177354054000000000",
```

|---|---|
| `site` | いまは `kakuyomu` だけ |
| `workId` | 作品管理の画面の URL の作品ID。受け手がどの作品かを探すのに使う |
| `pageUrl` | 読んだ画面（`?` と `#` から後ろは落とす） |

### 4.10 受け手が守ること

ヘルパーの一線（[2章](#2-越えない一線)）は、受け手の側が守らないと意味が無くなる。受け手には次を求める（統合小説執筆環境は満たしている）。

1. **合図はパスだけを見る。** クエリを読まない・記録にも残さない。合図は誰でも作れる（ウェブページのリンク1つで開かせられる）ので、「クリップボードを見に来て」以上の意味を持たせない
2. **封筒を検査してから使う。** 版の完全一致・知っているサイトか・欠けた欄・数でない値。**1件でも読めなければ、その封筒ごと取り込まない**（部分取り込みをすると、作者には「取り込んだ」としか見えず抜けに気づけない）。束は1件ずつ検査し、読めない件があっても残りは止めない
3. **作品を照合する。** 封筒の `site`・`workId` を受け手の作品の記録と突き合わせ、合わなければ取り込まない。**誰の作品でも開けるページ（Narou.fun・カクヨムのアクセス数）の封筒は厳しく**照合する（作品IDが無い・登録が無いなら取り込まない）。推し量って作品を決めない（数字が別の作品に混ざると、あとから分けられない）
4. **追記で持ち、二重に積まない。** 同じ封筒を2度受けても記録が増えない。渡し直し（「もう一度渡す」）を安全にするため
5. **断るときは理由を言う。** 黙って終わると、押した作者には故障に見える
6. **クリップボードは作者の私物。** 封筒の目印が無いものは、中身も指紋も残さない
7. **受け手もサイトへ通信しない**（ヘルパーが読んだ数を、受け手がサイトへ問い合わせて補ったりしない）
8. ヘルパーが受け取らないことにしたサイト（なろう本体・pixiv・ハーメルン・note）の封筒は受け取らない

### 4.11 ヘルパーが守ること

1. 封筒は [4.4](#44-封筒の共通の決まり) の形で作り、版を勝手に上げない
2. 合図にデータを載せない。合図の先を1か所（`common/actions.js`）にまとめる
3. **受け手の検査を写しで持たない。** 封筒の読み口・率の式は受け手の本物に読ませて確かめる（[4.13](#413-約束を確かめるテスト)）
4. 渡した束は控え、届いたか分からない前提で渡し直せるようにする

### 4.12 受け手を足すとき決めること

統合小説執筆環境のほかのアプリとも連携する予定がある（作者、2026-10-12）。足すときに決めること：

1. **起こす合図**：手元のアプリなら独自のスキーム（`<scheme>://…`）か、合図なし（作者が受け手の画面で「貼り付けて取り込む」）か。ウェブのアプリならリンクを開くことは通信に近づくので、合図を持たず貼り付けだけにするのを基本とする
2. **受ける封筒の種類**：4つ全部か一部か。受け手ごとに封筒の形を変えない（同じ形を読んでもらう）。受け手に固有の欄が要るなら、省いてよい欄として足す
3. **どの受け手を呼ぶかの選び方**：いまの「統合小説執筆環境へ渡す」の入・切を、受け手を選ぶ設定に広げるのか、受け手ごとの入・切にするのか。合図の定数を受け手ごとの表にする
4. **画面の文言**：「統合小説執筆環境へ渡す」「VS Code が前に出なければ」のように受け手の名前を決め打ちしている文言を、受け手に合わせて出し分ける
5. **番人のテスト**：「受け手を呼ぶ場所が1つ」（`test/redLine.test.js`）を、受け手の表の1か所に読み替える。合図にデータを載せないことは変えない
6. **約束を確かめるテスト**：その受け手の読み口に封筒を読ませる道（[4.13](#413-約束を確かめるテスト)）を作れるか
7. 受け手が [4.10](#410-受け手が守ること) を満たしているか

### 4.13 約束を確かめるテスト

封筒の形は2つの製品の間の取り決めなので、**確かめ方を写さず、受け手の本物に読ませる**。統合小説執筆環境のソース（`novel-ai-assistant`）がこのフォルダーの隣にあるときだけ走り、無ければその件だけ飛ばす。受け手を足したら、その受け手の読み口にも同じように読ませる道を作る。

| テスト | 読ませる相手 |
|---|---|
| `test/readEnvelope.test.js` | 読者の反応の封筒 → `src/core/readerStatsEnvelope.ts` |
| `test/contestRead.test.js` | 公募の一覧の封筒 → `src/core/contestListing.ts` |
| `test/history.test.js` | 集計の率 → `src/core/readerRates.ts`（式を写しで持つので、片方だけ変わった日に気づくため） |

**章立ての封筒（`novelai-chapters`）は、まだ受け手の読み口（`src/core/chapterEnvelope.ts`）に読ませていない**（`test/chapterRead.test.js` は合図の行き先までを見る）。引継ぎ書の既知の課題に置く。

## 6. 貼り込みの決めごと

1. **認証情報に触れない**：ログインは作者が普通に行う。パスワード欄のあるページでは何もしない（「ログイン画面では動きません」）。セッション切れのリダイレクト先でも同じに落ちる
2. **貼り込み先の照合**：封筒の `site` とページのドメイン、話の作成画面か、封筒の `workId` と投稿画面の URL の作品ID を突き合わせる（複数作品・複数タブで別の作品の画面を開いていることがある）。違えば埋めずに理由を言って止める
3. **空でない欄には黙って入れない**：欄に既に文があれば確認を出し、断れば何もしない（書きかけの前書きを黙って消さない）
4. **見当で当たった欄は確かめる**：`#body` や `contenteditable` のように、どのページにもあり得る形で当たった欄は、空でも一度訊く。サイト固有の形（`textarea[name="body"]` など）で当たり、かつ空のときだけ黙って入れる。結果には入れた欄を `本文欄（textarea#episode-body）` の形で出す（見覚えのない名前なら、貼り込み先が違う合図）
5. 欄探しは投稿フォームの起点（`formScopes`）の配下に限る。起点が見つからずページ全体を探したときは、当たった欄を見当扱いにする
6. 画面が入力に気づくように、ネイティブの setter で値を入れて `input`／`change` を配る（React などで作られた画面対策）
7. 欄が見つからなければ「ページの形が変わったようです」と言って何もしない（黙って違う欄に入れない）
8. **最後の確認は送信＝作者の手**：埋めたあと、作者がサイトのプレビューで確かめてから投稿ボタンを押す。これが自動の受け渡しに対する最後の確認で、だから送信を自動にしない
9. **章の選択（0.15.0。表に `chapter` の欄を持つサイト＝アルファポリスだけ）**：封筒に `chapter` があり、題と本文を入れたあとにだけ触る（ログイン画面・本文欄が無い・確認で断った・作品の取り違えのときは触らない）。選択肢の字と封筒の章を、前後の空白・続く空白・全角の英数と空白をならして（NFKC にはしない。①や半角カナまで変わるため）**完全一致で比べ、ちょうど1つ当たったときだけ選ぶ**。`value` が空の選択肢（「選ばない」の項目）は候補にしない。0件・2件以上・欄が無い・選べない状態（disabled）なら選ばず、結果に「章は選べませんでした（理由）。章はご自分で選んでください。」を添える（題と本文はそのまま）。選んだら結果に「章：◯◯」を添え、select にもネイティブの setter で入れて `input`／`change` を配る。見当は select だけに当たる形で、汎用の見当は持たない（確認を出す道が無いので、見当違いの選択を黙って変えないため）。投稿フォームの起点が見つからないときも探さない。判定は `common/guard.js` の `pickChapterOption`（`test/chapterPick.test.js`・`test/fillChapter.test.js`）

**欄の指定**（`content/sites.js`。ページの形が変わったら直すのはここだけ）：

| サイト | 話の作成画面 | 欄 |
|---|---|---|
| カクヨム（2026-09-22 実機） | `/my/works/{作品ID}/episodes/new` | 起点 `form#episode-editForm`、題 `input#episodeTitle-input[name="title"]`、本文 `textarea#episodeBody-input[name="body"]`（textarea なので改行は保たれる）。`id` を先、`name` を後に当てる |

### 7.4 Narou.fun の作品ページ（0.6.0・0.7.0）

2026-11-01 のリニューアル（サイトの名は「なろうファンDB」）に合わせて、0.14.2 で URL と形を直した。

- 範囲は `https://db.narou.fun/novels/*`（`content_scripts.matches`。`host_permissions` は置かない）。表 `content/statsSites.js` の `narouFun` 行（`hosts: ["db.narou.fun"]`、`/novels/{Nコード}` だけ。大文字も小文字も受け、照合と記録では小文字にそろえる）。リニューアル前の `/works/{Nコード}` は 404 になったので読まない
- **ページの形**（2026-11-01、作者の Chrome と同じ URL から取ったサーバーの HTML）：数は区画ごと。`section[aria-labelledby="pts"]` に `div > span「総合ポイント」+ span「4,808」`、`section[aria-labelledby="react"]` に `dl > div > dt「ブクマ」+ dd「1,111」`（感想・レビュー・評価者数・平均評価・週間読者も）、`section[aria-labelledby="spec"]` に `dt「データ取得」+ dd「2026/10/31」`

- 読む数は [4.6](#46-読者の反応の封筒-novelai-statsヘルパー-→-受け手) の写しの7つ（リニューアル前と同じ）。**読まないもの**：平均評価（評価P ÷ 評価者数の10点満点の点の平均で、なろうのバックアップの「評価平均」〔星の平均〕と尺度が違う）、評価頻度（評価者数 ÷ ブクマ。作者の評価率〔÷ 第1話の PV〕とは別物。リニューアル後の画面には無い）、ブクマ×2、日間ポイント・日間ランクイン・最高順位・文字数・会話率・あらすじ、「解析」の行き先（KASASAGI）。題は作品名のためだけに読む（0.13.1）。**キーワードと形式は 0.16.0 から読む**（タグと連載の状態として。形式は「連載中」「完結」の字だけを見て、話数は読まない）
- **日ごとの表**（2026-11-01 の形）：`div[role="table"][data-range="7"|"14"|"all"]` の3つが**はじめから全部ページにある**（14 と all は hidden。画面の切り替えは見せ方だけ）。見出しは `span[role="columnheader"]` の「日付」「ブクマ」「評価P」、行は `div[role="row"]`、枡は `span[role="cell"]`（「10/30」・`span「1,111」+ span「±0」`）。ページ送りも表示件数も無い。全期間は直近30日分まで（作者の作品で29行、1日抜け）。**全期間の表を先に読み、14日・7日の表は足りない日を埋めるだけ**（同じ日は最初の1行を採る）。表の `data-tsv` 属性（全行の文字）は長いので読まない
  - **前の日の累計との差を、その日の数（`period: "day"`）にする**（ブクマ→`bookmarks`、評価P→`narou_ratingPoints`）。数の後ろの差（「±0」「+1」「-1」）は読まない（最初の行は前の日が無いのにサイトが「±0」と置く）。**前の日の行があるときだけ**差を取る（日が抜けていたら2日ぶんを1日にしない）。「-」の枡はその欄だけ差を取らない。列は見出しの名前で当て、並びに頼らない。減った日は負のまま渡す
  - **表の最初の日は捨てる**（差が取れない）。30行なら最大29日ぶん（作者の作品では27日）
  - 0.7.0〜0.14.1 の「表示件数を30にしてから、もう一度」の知らせはやめた（ページ送りが無くなったため）
  - **年は読んだ日から補う**：去年・今年・来年のうち読んだ日にいちばん近い日。読んだ日より先の日（リアルタイム表示の明日）は読まない。60日より離れる日付は年を当て推量することになるので読まない。閏日はその年に在るときだけ
- **記録の日時はページの「データ取得」の日付**：作品の基本情報の「データ取得 2026/10/31」（dt と dd を包む div の字）を、**その日の 0:00（日本時間）**として UTC の ISO にして `readAt` に。時刻はページに無いので当て推量で足さない。0:00 にそろえると、同じ日のデータを何度読んでも記録の日時が同じになり、受け手で二重にならない。`readAtBasis` は `"fetched"` のまま（封筒の形は変えない）。読めなければ押した時刻へ落とし、`"clicked"` で区別する。表のいちばん新しい行は「データ取得」の前の日だった（10/30 と 2026/10/31。リニューアル前は同じ日）
- **作品名**は大見出し（`h1`）の字。無ければページの題「{作品名}のブクマ・評価ポイント推移とランキング | なろうファンDB」から決まり文句を剥がす
- Narou.fun には話ごとの PV が無いので、なろうの作品の率は出ない（集計でも理由として出す）

### 7.5 溜まりと控え（0.9.0）

- 溜まりの上限は **50画面・200万字**（データの文字数の合計）。越えたら古いものから消す
- **渡すと溜まりは空になる。** 渡した束は控えとして**次に渡すまで・長くても7日**残し、説明のページの「もう一度渡す」で渡し直せる（届いたかが分からないため）。「溜まりを空にする」で渡さずに消せる
- 保存するのは、溜まり・控え・覚えた作品（サイト・作品ID・覚えた日）・訊きかけの作品・集計のための記録（`readerHistory`）・「統合小説執筆環境へ渡す」の入・切（`helperSettings`）だけ。すべて `chrome.storage.local`
- 「統合小説執筆環境へ渡す」を切っている間は溜めない。切る前の溜まりは残す

### 7.6 記録と簡易集計（0.10.0）

- 記録は溜まりと別のもの。受け手へ渡しても、溜まりを空にしても消えない。**覚えた作品だけ**を記録し、覚えた作品から外すとその作品の記録も消す
- **同じ作品・同じ日の分は1つに畳み、欄ごとに新しい数で置き換える**（開き直すたびに増えない）。読める欄が違う画面は欄ごとに合わせる。古い読み取りで新しい数を上書きしない
- 話ごとの数は日ごとに残さず、話ごとにいちばん新しい数だけを持つ（率に要るのはそれだけ。219話を日ごとに残すと半年で保存の持ち分を食い尽くす）
- 上限は **20作品・180日（月ごとの数は24か月）・150万字**。越えたら、いちばん長く記録していない作品から、日はいちばん古い日から消す（どの作品も最後の1日は残す）
- 作品名（0.13.1）は作品ごとにいちばん新しい1つだけ持つ
- 集計に出すもの：見出し（作品名と作品ID。**72字幅〔全角は2〕で折り返す**——長い題で枠の右端から作品IDが出ていた。0.16.0。枠は表の桁を揃えるため折り返さない）・連載の状態とタグの1行（0.16.0。いちばん新しく読めたもの。0個と分かれば「タグ：なし」、分からなければ出さない。記録の省いてよい欄 `tags`・`completion` で、記録の版は1のまま）・いまの数・日ごとの数（直近14日、字の棒つき）・記録した日ごとの数と前の記録からの増え方（間が1日より空いた日は `*`）・3つの率。外の字体やライブラリは読み込まず、表と棒は拡張の中で組む
- **率の式は受け手（統合小説執筆環境）と同じ**（`test/history.test.js` が受け手の本物と突き合わせる）：
  - 離脱率 ＝ 1 − 基準の話の PV ÷ 第1話の PV。基準の話は、更新から読んだ時点までに**72時間以上**たっていた話のうち話数がいちばん大きい話
  - ブックマーク率 ＝ 作品全体のブックマーク（カクヨムはフォロワー）÷ 第1話の PV
  - 評価率 ＝ 評価した人数 ÷ 第1話の PV（カクヨムはレビュー、なろうは評価者数）
  - 材料が欠けたら 0% と書かず、足りない材料を書く

### 7.8 ランキングの画面とお祝い（0.19.0）

作者の指示（2026-11-02）「ランキング画面に自作があったら吹き出しでお祝い、そして取得」「ランキングに入ったり順位が上がった場合、風船とか花火（規模により変動）」。受け手との形の取り決めは [4.7](#47-束-novelai-stats-bundleヘルパー-→-受け手090) の `rankings`。

- **対象**：カクヨム `https://kakuyomu.jp/rankings/{ジャンル}/{期間}?work_variation=…&page=N`、アルファポリス `https://www.alphapolis.co.jp/novel/ranking/{hot|annual|completed}`。表は `content/statsSites.js` の `RANKING_SITES`、読むのは `content/read.js` の `readRankings`（ページの文字を読んでよいファイルは増やしていない）
- **なろう（syosetu.com 系）と Narou.fun のランキング（`db.narou.fun/ranking/*`）では何もしない**（作者の判断 2026-11-02「なろうではヘルパーからの取得はしないでください」「なろうのランキングの画面では何もしない」）。matches にも入れない。Narou.fun の作品ページの読み取り（[7.4](#74-naroufun-の作品ページ060・070)）は変えない
- **読むのは覚えた作品の行だけ**：裏方がそのサイトの覚えた作品の作品IDを添えて頼み、読み取り係は1作品の枠ごとにリンクの行き先（href）から作品IDを取り、一致した行だけ順位と作品名を読む。ほかの行の順位・作品名は読まない・溜めない・渡さない。**覚えた作品が無いサイトでは、ページへ頼まない**（自動で取得するかも訊かない）。返ってきた順位も、裏方が覚えた作品のものだけに絞って形を確かめる
- **1作品の枠**：カクヨムは順位の枠（`div[class*="RankingWorkBox_rank__"]`）と作品の枠（`…_contents__`）が兄弟で、両方を1つずつ持つ**いちばん内側の div**を1作品とする（包む要素のクラス名を確かめていないため）。作品IDは作品の枠の `h3` の中の `/works/(\d+)`。アルファポリスは `section.c-content`、順位 `span.c-content__rank`、作品IDは `h2.c-content__title` のリンクの `/novel/{作者ID}/{作品ID}` の後ろ（`data-citiid` は作者IDなので使わない）。枠が1つも無ければ「ページの形が変わった」として何も返さない
- **区分**：`board` はカクヨムが `rankings/{ジャンル}/{期間}/{work_variation（既定 long）}`（page は入れない）、アルファポリスが `novel/ranking/{種類}`（`?category=` があれば足す）。`boardLabel` は見出し（h1、80字まで、「ランキング」を含むときだけ）、読めなければ URL から組む。カクヨムの `genre` はジャンルの名前の表（画面の字との対応は未確認。表に無い名前は見出しから切り出す）、総合は省く
- **開いたとき**：autoRead の種類はサイトごとに1つ（`kakuyomu|rankings`・`alphapolis|rankings`）。区分ごとには訊かない（数百通りある）。**更新しただけでは「自動」にしない**（`askFirst`）。承認していれば、開いてから少し待って1回だけ読む。覚えた作品が載っていなければ何も言わない
- **押したとき**：その場で読む。まだお祝いしていない順位があればお祝いだけ（続けて VS Code を前に出すと吹き出しが閉じるので、その回は渡さない）。もうお祝いした順位だけなら、ほかの読者の反応の画面と同じく「まとめて渡す」。「統合小説執筆環境へ渡す」を切っていれば順位は溜めず、お祝いとお知らせだけ
- **印**：ランキングの画面は「位」（`#b7791f`）。覚えた作品が載っていたのにタブが前に無くてお祝いを出せなかったタブは「祝」（`#d53f8c`）。全体の「読3」は読者の反応の画面の数のまま（順位は数えない）。ただし順位だけ溜まっていても、ほかの画面で押せば渡せる
- **溜める**：溜まり（`helperState`）の `rankings`。鍵 `site|workId|board|date` で上書き。**上限300件**（1件300字ほど。読んだ日時の古いものから落とす）。渡すと控えへ移り、もう一度渡すにも入る。「溜まりを空にする」で一緒に消える。集計の記録（`readerHistory`）には入れない
- **お祝い**：アイコンの吹き出し（`bubble.html`、`mode: "celebrate"`）で「〈作品名〉が〈boardLabel〉で N 位に入っています。おめでとうございます！」（上がったときだけ前の順位を添える）。**鳴らす鍵は `site|workId|board|date|rank` で一度だけ**（同じ日に順位が動けばもう一度）。**タブが前に無ければ鳴らさず「祝」の印だけ**（お知らせにも回さない）。前にあるのに吹き出しを出せなければ、お知らせで文だけ。**鳴らした印は実際に出せたときだけ残す**。記憶は別の鍵 `rankingMemory`（鳴らした印と前に見た順位、それぞれ300件まで）
- **演出の規模**（`common/rankings.js`）：前に見た順位（作者に見せた最後の順位）と比べる。下がった・同じ → 無し（文だけ）／1位 → 大きな花火／10位以内（`TOP_RANK_FOR_FIREWORKS`）か大きな上昇（半分以下の順位で、しかも10位以上の上昇。`BIG_RISE_RATIO`・`BIG_RISE_MIN_STEPS`）→ 花火／初めて入った・小さな上昇 → 風船。複数の作品が載ったら大きいほう
- **演出の作り**：部品（風船6つ・花火3発ぶんの火花）は `bubble.html` に書いておき、`bubble.js` が `data-effect` を付けて `hidden` を外すだけ（要素を作らない）。動きは `bubble.css` の CSS の図形とアニメーションだけで、外の画像・字体を読み込まない。**`prefers-reduced-motion: reduce` では出さない**（`effectToShow` と CSS の両方）。演出は吹き出しの中だけで、サイトの画面には何も差し込まない

## 11. 検討して採らなかったもの

### 11.1 ブックマークレット（2026-09-05）

| 観点 | ブックマークレット | Chrome 拡張 |
|---|---|---|
| 導入 | ブックマークに登録するだけ | インストールが要る |
| CSP | **ページの CSP に止められることがある**（Chrome は `javascript:` の実行にページの CSP を適用する。外部スクリプトで逃げると CSP にも「通信しない」にも反する） | 隔離された世界で動き、影響を受けない |
| 受け渡し | クリップボードは許可の問い頼みでブラウザ差が大きい。`prompt()` への手貼りは長い本文で切れる | 権限で読める |
| 更新 | 直すたびに登録し直す | ブラウザが更新する（ストア配布時） |
| 大きさ | URL の長さ制限（数KB） | 制限なし |

**本命は Chrome 拡張**。封筒の形を共通にしてあるので、CSP の緩いサイト向けに同じ封筒を読む最小のブックマークレットを後から足せる。

### 11.2 受け渡しの選択肢

| 案 | 判定 |
|---|---|
| クリップボードの封筒 | **採用**（[4.2](#42-経路はクリップボードだけ)） |
| ローカルファイル渡し | 毎回ファイル選択の手数が増える。封筒が大きすぎる場合の逃げ道として設計だけ残す |
| localhost のサーバー／ネイティブメッセージング | 不採用（常駐が増え、構成が重い） |

### 11.3 SNS（X）の投稿画面への貼り込み

ヘルパーでは作らない。X には公式の貼り付け口 Web Intent（`https://x.com/intent/post?text=…`）があり、受け手がそれを開けば足りる（統合小説執筆環境が実装済み）。X の画面は動的な DOM で最も壊れやすく、公式の口があるのに DOM を触るのは規約面でも保守面でも損。

### 12.1 画面の自動テスト（E2E。2026-10-12）

作者の裁定（2026-10-12）「Chrome のテストも、拡張機能をアップデートしたら後は自動でできそう」→「今から作る」。README の「実機で確かめること」のうち、**開いた・答えた・押したときに起きること**を機械で毎回なぞる。

- `npm run test:e2e`（`vitest.e2e.config.mjs`）。**`npm test` には入れない**（1件ごとにブラウザを起こすので遅い）
- **ブラウザは Playwright の Chromium**（`playwright` 1.63.0、`channel: "chromium"`）。ブランドの Chrome は 137 から `--load-extension` を受けない。既定の headless（headless shell）は拡張を読まないので、完全版の新しい headless を使う。`--disable-extensions-except`・`--load-extension` でこのフォルダーをそのまま読み込む（ビルド工程が無い）
- **画面の外（headless）で起こす。** 作者の画面の前面を取らない。1件ごとに一時のプロフィール（`%TEMP%\nph-e2e-*`）を作り、終わったら必ず閉じて消す。走りの最初と最後にも、30分より古い残りを消す
- **本物のサイトへは行かない。** 全部の通信を止め、見本の URL にだけ `test/e2e/fixtures/` の HTML を返す（ログインが要り、機械にパスワードを入れない決まり）。見本は読み取り係が当てにする要素の形だけを最小限で置いたもので、本物の写しではない（題・数はすべて架空）。アルファポリスの見本は置くだけ（0.17.0 から読むが、画面の自動テストはまだ無い）
- **製品のコードにテスト専用の口を足さない。** 見るのは裏方の chrome API の呼ばれ方で、テストの側から包んで記録する（`support/helperBrowser.js`）：お知らせ（**記録だけして出さない**）・吹き出し（`setPopup`／`openPopup`。通ったか断られたかで、どちらが出たか分かる）・受け手の合図（`vscode://` へ向ける `tabs.update` は**記録だけして向けない**。route は http/https しか止められない）・クリップボードへ置く頼み。保存は裏方から `chrome.storage.local` を読む
- **届かないもの**：ツールバーのアイコンそのもの・吹き出しの中・お知らせのボタンは Playwright から押せない。アイコンは、押したときに Chrome が呼ぶのと同じ裏方の関数（`実行する`）を呼んで代える。問いへの答えは、同じ `bubble.html` を同じ問い合わせの部分でタブに開いて押す（吹き出しから答える道と同じ `bubble-answer`。お知らせのボタンの道は通らない）。吹き出しの見た目・位置・字が読めるか、Windows の通知が出るか、`vscode://` で VS Code が前に出るかは実機の領分
- 作者が使っているパソコンでは走らせない（ノートPCで走らせる）
