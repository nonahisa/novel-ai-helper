## 1. デベロッパー登録（初めての1回だけ）

1. Chrome で https://chrome.google.com/webstore/devconsole を開き、ストアで使う Google アカウントでログインする
   （Google アカウントの2段階認証が要ります。まだなら先に入れる）
2. デベロッパー契約を読んで**同意**し、**登録料を支払う**
3. ［アカウント］の画面で、公開する名前（発行者名。例：nonahisa）と連絡先のメールアドレスを入れ、届いたメールで**確認**する
4. 取引業者かどうかの申告の欄があれば答える。ヘルパーは無料で、売上もないので「取引業者ではない（非トレーダー）」が近い
   （EU の決まりによる欄。どちらにするかは作者の判断）

## 2. ZIP を作る（PowerShell）

```powershell
Set-Location C:\Users\nonah\Documents\novel-post-helper
npm run pack
```

`dist\novel-ai-helper-0.17.1.zip` ができます（36ファイル・約177KB）。中身は拡張の実行に要るファイルだけで、
テスト・文書・ストアの材料・node_modules は入りません（2026-11-01 に確かめた）。

## 5. ［プライバシーへの取り組み］（Privacy practices）

文はすべて `store/permissions.md` にあります。各欄に、同じ見出しの囲みの中を貼ります。

| 欄 | 入れるもの |
|---|---|
| 単一用途の説明（Single purpose description） | 「単一用途の説明」の囲み |
| 権限ごとの理由（Permission justification） | `clipboardRead`・`clipboardWrite`・`activeTab`・`notifications`・`contextMenus`・`offscreen`・`storage` の7つ。それぞれの見出しの囲み |
| ホストの権限の理由（Host permission justification） | 「ホストの権限の理由」の囲み。**字数の上限で入りきらなければ**、その下の「短い版」（約800字）を貼る |
| リモートコードを使うか（Are you using remote code?） | **いいえ（No, I am not using remote code）**。理由の欄があれば「リモートコードの使用」の囲み |
| 集めるデータの種類 | 「ウェブ履歴」と「ウェブサイトのコンテンツ」の**2つだけ**に印。ほか（個人を特定できる情報・健康・財務と支払い・認証情報・個人的なコミュニケーション・位置情報・ユーザーのアクティビティ）は印を付けない |
| 3つの宣誓 | 3つとも印を付ける（第三者に販売・転送しない／単一用途と関係のない目的に使わない／信用度の判断や融資に使わない） |
| プライバシーポリシーの URL | `https://github.com/nonahisa/novel-ai-helper/blob/main/PRIVACY.md` |

- 「ウェブ履歴」に印を付けるのは作者の裁定（2026-10-11「申告する」）。理由と、印を付けない種類の根拠は `store/permissions.md` の「データの利用」の表
- 上の URL は、リポジトリが公開のままなら開けます（2026-11-01 に公開を確かめた）。貼る前に一度開いて、PRIVACY.md が出るか見てください

## 7. 審査に出す（作者が押す）

1. 右上の［審査のために送信］（Submit for review）を**作者が押す**
2. 出てくる確認で「審査に通ったらすぐ公開する」かどうかを選ぶ。後で自分で公開したければ、印を外す（Google の案内では、通ってから一定の日数のうちに公開する）
3. 審査の結果は、登録したメールとダッシュボードに届く

## 8. 載ったあとにすること（Claude に頼めばよい）

- ストアの URL（`https://chromewebstore.google.com/detail/…/<拡張 ID>`）を、統合小説執筆環境の `HELPER_DOWNLOAD_URL`
  （`core/postingEnvelope.ts`）へ差し替えてもらう
- 引継ぎ書の「いまの状態」の Chrome ウェブストアを「公開」に、`docs/実装の残り.md` の「Chrome ウェブストアへの公開」を `[x]` に
- 2回目以降を自動で出すなら、`store/自動公開の準備.md` を進める（拡張 ID と発行者 ID は、この初回のあとで分かる）

## 審査で訊かれやすいこと（備え）

- **権限が多い・入るページが多い**：権限ごとの理由とホストの権限の理由に、1つずつ「何のために・何をしないか」を書いてある
- **ウェブサイトのコンテンツを読む**：読むのは画面に出ている数・作品名・タグ・連載の状態と公募の一覧の短い字だけで、本文は読まない。通信しない（`test/redLine.test.js` が見張る）
- 断られたら、届いたメールの理由をそのまま Claude に渡してください（直す所を `store/` と、要ればコードで直します）
