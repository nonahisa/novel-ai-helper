# 自動公開の準備（2回目以降の版を GitHub Actions で出す）

2回目以降の版を、GitHub Actions のワークフロー `.github/workflows/publish-chrome-web-store.yml` で
Chrome ウェブストアへ上げて審査に出すための準備です。**作者が1回だけ行います。** 鍵の値は作者だけが扱い、
Claude には見せません（チャットにも貼らないでください）。

- 書いた日：2026-11-01（Google の公式の手順 https://developer.chrome.com/docs/webstore/using-api をこの日に読んで合わせた）
- Google Cloud・ダッシュボードの画面の項目名は、Claude が画面で確かめていません。名前が少し違っていたら、いちばん近いものを選んでください

## 0. 先に済ませること：初回はダッシュボードで手で出す

**ストアに拡張の枠が無いと、API では上げられません。** 初回は `store/提出の手順.md` のとおり、ダッシュボードで
ZIP を上げて審査に出してください。枠ができると、次の2つが分かります（あとの手順5で使います）。

| 名前 | どこで見るか |
|---|---|
| 拡張 ID（アイテム ID） | ダッシュボードで拡張を開いたときのアドレス欄の、英小文字32字の部分。ストアのページのアドレスの最後にも出ます |
| 発行者 ID（パブリッシャー ID） | ダッシュボードの左の［発行者］（Publisher）→［設定］（Settings） |

また、ダッシュボードで「公開／限定公開」などの見え方を手で変えたあとは、一度ダッシュボードから手で公開するまで、
API では審査に出せません（公式の文書の注記）。

## 1. Google Cloud でプロジェクトを作り、Chrome Web Store API を有効にする

1. Chrome で https://console.cloud.google.com/ を開き、ストアと同じ Google アカウントでログインする
2. 上の帯のプロジェクトの選択 →［新しいプロジェクト］。名前は「novel-ai-helper-publish」など何でもよい →［作成］
3. 作ったプロジェクトを選んだまま、上の検索欄に「Chrome Web Store API」と入れて開き、［有効にする］を押す

## 2. OAuth の同意画面を作る

1. 左のメニュー →［API とサービス］→［OAuth 同意画面］（新しい画面では［Google Auth Platform］）
2. ユーザーの種類は［外部］（External）→［作成］
3. アプリ名（例：novel-ai-helper-publish）、ユーザー サポートのメール、デベロッパーの連絡先（どちらもご自分のメール）を入れて保存
4. スコープの画面は何も足さずに［保存して次へ］
5. テストユーザーに、ご自分のメールを足して保存

> **2026-11-04 に作者と通したときの実際**（新しい画面「Google Auth Platform」）：同意画面は［概要］の「プロジェクト構成」で、アプリ情報 → 対象（外部）→ 連絡先 → 終了（ポリシーへの同意）→［作成］。［対象］の［アプリを公開］は、［ブランディング］に**ホームページとプライバシーポリシーのリンク**を入れるまで押せなかった。ホームページ `https://github.com/nonahisa/novel-ai-helper`、プライバシーポリシー `https://github.com/nonahisa/novel-ai-helper/blob/main/PRIVACY.md`、承認済みドメイン `github.com` で保存でき、「本番環境」にできた。ロゴは上げない（上げると Google の確認が要る）。上の帯に Google Cloud の無料トライアルの案内（アップグレード）が出るが、押さない

### テスト中のままにしない（大事）

同意画面が「テスト中」のままだと、**更新用トークン（手順4で取るもの）が7日で切れます**
（Google の文書 https://developers.google.com/identity/protocols/oauth2 に「7日で切れる」とある。2026-11-01 に確認）。
切れると、2回目以降の自動公開が毎回「invalid_grant」で止まります。

- 同意画面の［アプリを公開］（新しい画面では［対象］→［アプリを公開］）を押して「本番環境」にしてください
- 本番にしても、Google の審査（確認）は受けなくて使えます。ただしログインのときに「Google はこのアプリを確認していません」と
  出るので、［詳細］→［（アプリ名）に移動］で進んでください（自分のアプリなので問題ありません）。
  **本番にしたあと、審査なしで本人が使えることは、Claude は画面で確かめていません**（未確認）。手順4で進めなければ、
  テスト中のままにして、7日ごとに手順4をやり直すことになります

## 3. OAuth のクライアントを作る

1. 左のメニュー →［API とサービス］→［認証情報］（新しい画面では［クライアント］）
2. ［認証情報を作成］→［OAuth クライアント ID］
3. アプリケーションの種類は［ウェブ アプリケーション］
   （公式の手順はウェブ アプリケーション＋OAuth 2.0 Playground の形。デスクトップの種類を選ぶ道もあるが、公式の手順に合わせた）
4. 名前は何でもよい。［承認済みのリダイレクト URI］に次の1行を足す

   ```
   https://developers.google.com/oauthplayground
   ```

5. ［作成］。出てきた**クライアント ID** と**クライアント シークレット**を、このあと手順5で GitHub へ入れるまで、
   画面を開いたままにしておく（メモ帳などに保存するなら、終わったら消す）

## 4. 更新用トークンを取る（OAuth 2.0 Playground）

1. Chrome で https://developers.google.com/oauthplayground を開く
2. 右上の歯車 →［Use your own OAuth credentials］に印を付け、手順3のクライアント ID とクライアント シークレットを入れる
3. 左の［Step 1］の下の入力欄（Input your own scopes）に、次の1行を入れて［Authorize APIs］

   ```
   https://www.googleapis.com/auth/chromewebstore
   ```

4. ストアと同じ Google アカウントでログインし、許可する（「確認していません」と出たら手順2の注のとおり進む）
5. ［Step 2］で［Exchange authorization code for tokens］を押す
6. 出てきた **Refresh token** を手順5で GitHub へ入れる（Access token は使いません）

> 2回目以降の自動公開が「invalid_grant」で止まったら、更新用トークンが切れたか取り消されています。この手順4だけをやり直し、
> 手順5の `CWS_REFRESH_TOKEN` を入れ直してください。
>
> **クライアント シークレットが伏せられて読めないとき**（Google Cloud は作ったあとのシークレットを見せないことがある）：
> Google Cloud の［API とサービス］→［認証情報］→ OAuth クライアント `publish-workflow` を開き、シークレットを**新しく1つ足す**。
> 足したシークレットで手順4の2から行い、手順5の `CWS_CLIENT_SECRET` と `CWS_REFRESH_TOKEN` を**両方**入れ替える
> （2026-11-07 に作者がこの形で通した。古いシークレットは、同じ日の夜に作者が消した——作成日で見分け、無効にしてから削除）

## 5. GitHub に Environment と Secrets を作る

### 5-1. Environment（鍵の置き場）を作る（ブラウザ）

1. https://github.com/nonahisa/novel-ai-helper/settings/environments を開く
2. ［New environment］→ 名前に `chrome-web-store` と入れて［Configure environment］
3. ［Required reviewers］には印を付けない（**承認は挟まない**。2026-11-07 作者の決定で外した。
   それまでは `nonahisa` を承認者にして、動かすたびに［Approve and deploy］を押していた）
4. ［Deployment branches and tags］は［Selected branches and tags］にして `main` を足す
   （［Run workflow］で main 以外の枝を選んで動かしても、鍵に触れる段へ進まないようにするため。迷ったら［No restriction］のままでもよい）

### 5-2. Secrets を5つ入れる（PowerShell）

値は打ち込むときに画面に出ず、PowerShell の履歴にも残りません（`gh` が入力を待つ形）。
1行ずつ実行し、それぞれ訊かれたら値を貼って Enter を押してください。

```powershell
Set-Location C:\Users\nonah\Documents\novel-post-helper
gh secret set CWS_CLIENT_ID --env chrome-web-store --repo nonahisa/novel-ai-helper
gh secret set CWS_CLIENT_SECRET --env chrome-web-store --repo nonahisa/novel-ai-helper
gh secret set CWS_REFRESH_TOKEN --env chrome-web-store --repo nonahisa/novel-ai-helper
gh secret set CWS_PUBLISHER_ID --env chrome-web-store --repo nonahisa/novel-ai-helper
gh secret set CWS_EXTENSION_ID --env chrome-web-store --repo nonahisa/novel-ai-helper
```

| Secret | 入れる値 |
|---|---|
| `CWS_CLIENT_ID` | 手順3のクライアント ID |
| `CWS_CLIENT_SECRET` | 手順3のクライアント シークレット |
| `CWS_REFRESH_TOKEN` | 手順4の Refresh token |
| `CWS_PUBLISHER_ID` | 手順0の発行者 ID |
| `CWS_EXTENSION_ID` | 手順0の拡張 ID |

入れたか（名前だけ。値は出ません）を確かめるには：

```powershell
Set-Location C:\Users\nonah\Documents\novel-post-helper
gh secret list --env chrome-web-store --repo nonahisa/novel-ai-helper
```

（Claude に依頼された当初は4つでした。API の新しい版（v2）は発行者 ID も要るので、`CWS_PUBLISHER_ID` を足して5つにしています）

## 6. 2回目以降の出し方

1. いつもどおり版を上げ、GitHub Release `v<版>` に `npm run pack` の ZIP（`novel-ai-helper-<版>.zip`）を付ける
2. 次のどちらかでワークフローを動かす
   - ブラウザ：https://github.com/nonahisa/novel-ai-helper/actions/workflows/publish-chrome-web-store.yml →［Run workflow］→
     version に版（例 `0.17.2`）、source は `release`、reason に理由を入れて［Run workflow］
   - PowerShell：

     ```powershell
     Set-Location C:\Users\nonah\Documents\novel-post-helper
     gh workflow run publish-chrome-web-store.yml --repo nonahisa/novel-ai-helper -f version=0.17.2 -f source=release -f reason=機能
     ```

3. 承認を待たずに、そのまま ZIP を上げて審査に出します（2026-11-07 から。それまでは「Waiting」で止まり、
   作者が［Review deployments］→［Approve and deploy］を押していた）。**動かした時点で審査に出るので、版と source を確かめてから動かす**
4. 審査の結果はダッシュボードと、登録したメールに届きます

`source` を `repo` にすると、Release を使わず、タグ `v<版>` を取り出してワークフローの中で ZIP を作ります
（Release を出し忘れたとき用。手元で確かめた ZIP と同じものを出したいときは `release` を使う）。

## 7. 止まったとき

| ログに出る字 | 意味と直し方 |
|---|---|
| `Secrets の … がありません` | 手順5-2の名前の打ち間違いか、Environment の外（リポジトリの Secrets）に入れた |
| `アクセストークンを取れませんでした（HTTP 400、invalid_grant）` | 更新用トークンが切れた・取り消された。手順4からやり直す（同意画面がテスト中なら7日で切れる） |
| `アクセストークンを取れませんでした（HTTP 401、invalid_client）` | クライアント ID かシークレットが違う |
| `上げられませんでした（HTTP 400 …）` | manifest の版が、ストアにある版より上がっていないことが多い |
| `上げられませんでした（HTTP 403／404 …）` | 拡張 ID・発行者 ID の違いか、鍵を取った Google アカウントがストアのアカウントと違う |
| `審査に出せませんでした` | ZIP は上がっている。ダッシュボードから［審査のために送信］を押せば続きができる。見え方を手で変えたあとなら、一度手で公開する |

ワークフローは鍵の値をログに出しません（失敗したときに出すのは HTTP の状態コードとエラーの種類だけ）。
