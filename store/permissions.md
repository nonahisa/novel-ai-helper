# 審査欄に貼る文（プライバシーへの取り組み）

Chrome ウェブストアのデベロッパー ダッシュボード「プライバシーへの取り組み（Privacy practices）」の各欄へ貼る文です。
manifest.json（0.20.1）の権限・入るページの範囲を**1つ残らず**挙げてあります。権限を足した・減らした日は、ここも直してください
（`test/redLine.test.js` の「権限は最小のまま」が、manifest の権限の並びを見張っています）。

---

## 単一用途の説明（Single purpose）

```
小説の作者が、ご自分の作品の読者の反応（PV・ブックマーク・評価など）を投稿サイトの管理画面から記録して簡単に集計し、あわせて VS Code の拡張機能「統合小説執筆環境」とのあいだで原稿・読者の反応・応募先の候補（公募の一覧）・章立てをクリップボードで受け渡すための拡張機能です。どの機能も「自分の作品を書いて投稿・応募する作業」を助けるためのもので、対象はカクヨム・アルファポリスの作品管理と話の作成画面、なろうファンDB（db.narou.fun）の作品ページ、公募の一覧の3ページ（ノベルポータル2ページ・ツクリテミライ1ページ）、カクヨム・アルファポリスのランキングの画面（ご自分の作品が載っていれば順位を記録してお祝いするため。ほかの方の作品は読みません）に限られます。
```

## 権限ごとの理由（Permission justification）

manifest.json の `permissions` は7つです。

0.14.0（開いたときの自動取得と、アイコンの吹き出し）では**権限を足していません。** 吹き出しは `chrome.action.setPopup`・
`chrome.action.openPopup`（権限の要らない API）で出し、出せないときは今ある `notifications` のお知らせに回します。
答えと公募の一覧の棚は、今ある `storage`（`chrome.storage.local`）に置きます。開いたことは、これまでどおり
`content_scripts` の範囲のページからの知らせで知ります（`tabs` は足していません）。

0.19.0（ランキングの画面のお祝いと順位の取得）でも**権限を足していません。** 足したのは `content_scripts` の `matches` の2つ
（下の「ホストの権限の理由」）だけです。お祝いは 0.14.0 と同じ吹き出しで出し、順位とお祝いの記憶は今ある `storage` に置きます。
0.20.1（覚えた作品から外すと渡す分からも消す）も、0.20.0（話の番号を渡す・話の編集画面への貼り込み）でも**権限も入るページの範囲も変えていません**（manifest.json の違いは版の数字だけ）。話の編集画面は、今ある `content_scripts` の範囲の中です。なろうの管理画面には入らず、押したときの `activeTab` で URL を受け取るだけです。

### clipboardRead

```
話の作成画面でツールバーのアイコン（または右クリックの項目）を押したときに、VS Code の拡張機能「統合小説執筆環境」がクリップボードへコピーした原稿（題と本文）を読み、その画面の題と本文の欄へ入れるために使います。読むのは押したときの1回だけで、読んだ原稿は保存も送信もしません。
```

根拠：`background.js` の `貼り込む`（`クリップボードに頼む({ type: "read" })`）、`offscreen.js` の `読む`

### clipboardWrite

```
記録したご自分の作品の読者の反応の数と作品名を、VS Code の拡張機能「統合小説執筆環境」へ渡すためにクリップボードへ置きます。この拡張は通信をしないので、手元の別のアプリへ渡す道はクリップボードだけです。置くのは、作者がアイコンや説明のページのボタンを押し、「統合小説執筆環境へ渡す」を入れているときだけです。また、公募の一覧のページで作者がアイコンを押したときに、並んでいる公募（名前・締切・字数など）をクリップボードへ置きます（統合小説執筆環境で応募先を選ぶため）。投稿したあと、話の編集画面で作者がアイコンを押したときは、アドレス欄の URL にある作品IDと話の番号、その画面の題の欄の字をクリップボードへ置きます（統合小説執筆環境が、投稿した話とサイトの話を結び付けるため。本文は読みません）。
```

根拠：`background.js` の `束にして置く`・`もう一度渡す`（`type: "write"`）、どちらも `渡すか()` が偽なら置かない。公募は `公募を読んで渡す`（押したときだけ。1件も読めなければ置かない）。話の番号は `話の番号を渡す`（0.20.0。押したときだけ。URL の数字は `common/posted.js` の `matchPostedPage`）

### activeTab

```
ツールバーのアイコンや右クリックの項目を押したときに、そのタブのURLを見て、その画面でできること（貼り込み・読者の反応の記録・集計を開く・公募の一覧を読む・投稿した話の番号を渡す）を決めるために使います。小説家になろうの作品・話の管理画面では、この拡張はページに入らず、押したときにこの権限で渡されるアドレスの数字（小説番号・部分の番号）だけを使います。作品の取り違えを防ぐため、原稿の作品IDとURLの作品IDも照らし合わせます。tabs 権限は使わず、ほかのタブのURLは読みません。
```

根拠：`background.js` の `実行する`（`tab.url`）、`common/match.js` の `checkTarget`

### notifications

```
アイコンを押した結果（貼り込めた・記録した・渡した・できなかった理由）を Chrome のお知らせで伝えるために使います。この拡張はページの中に表示を差し込まないため、結果を伝える場所はお知らせか、ツールバーのアイコンの吹き出しだけです。また、どなたの作品でも開ける画面で「ご自分の作品ですか？」とお尋ねするボタン付きのお知らせと、取得できる画面を初めて開いたときに「開いたときに自動で取得しますか？」とお尋ねするボタン付きのお知らせ、開いたときに取得したことの「取得しました」のお知らせにも使います（アイコンの吹き出しを出せないときの代わり）。
```

根拠：`background.js` の `知らせる`・`訊く`・`自動取得を訊く`・`取得を知らせる`（`chrome.notifications.create`、ボタンは `onButtonClicked`）

### contextMenus

```
アイコンを押す代わりに、ページの右クリックからも同じ操作（本文を貼り込み・読者の反応を取得・自分の作品として覚える・集計を表示・公募一覧を取得・章立てを取得）を選べるようにするためと、ツールバーのアイコンの右クリックに「集計を表示」を出すために使います。ページの右クリックの項目は、この拡張が動くページにだけ出します。
```

根拠：`background.js` の `onInstalled`（`documentUrlPatterns` は manifest の matches、集計の項目は `contexts: ["action"]`）

### offscreen

```
クリップボードの読み書きのためだけに使います。Manifest V3 の service worker はクリップボードに触れないため、押したときだけ画面に出ない拡張のページ（offscreen.html）を開き、読み書きが終わったらすぐに閉じます。このページは投稿サイトのページには入りません。
```

根拠：`background.js` の `クリップボードに頼む`（`reasons: ["CLIPBOARD"]`、`finally` で `closeDocument`）

### storage

```
ご自分の作品として覚えた作品の、読者の反応の数（PV・ブックマーク・評価など）と、覚えた作品の一覧、設定（開いたときに自動で取得するかの、画面の種類ごとの答えを含む）を、この拡張の中の保存（chrome.storage.local）に残すために使います。公募の一覧のページを「開いたときに自動で取得する」と答えたときは、開いたときに読んだ公募の一覧（誰でも見られる募集の情報）をページごとに最新の1つだけ残します。集計（推移や率）はこの記録から計算します。保存はお使いのパソコンの中だけで、同期（chrome.storage.sync）は使わず、どこへも送りません。量には上限があり（記録は20作品・180日まで）、説明のページから消せます。原稿を入れたときは、作品ごとに最後の1件だけ、題・本文の字数・統合小説執筆環境が付けた札を残します（本文は残しません。7日で捨てます）。
```

根拠：`background.js` の `helperState`・`readerHistory`・`helperSettings`・`autoReadConsent`・`contestShelf`（0.14.0）・`lastPastes`（0.20.0）の読み書き（保存に触れるのは `background.js` だけ。`test/redLine.test.js` が見張る）

## ホストの権限の理由（Host permission justification）

`host_permissions` は**書いていません**。ページへ入る範囲は `content_scripts` の `matches` だけで、ダッシュボードではこれがホストの権限として扱われます。重なりを除いて17あります（0.12.0 で公募の一覧の6つ、0.17.0 でアルファポリスのマイページの4つ、0.19.0 でランキングの画面の2つを足した）。

```
この拡張がページの中で動くのは、次の画面だけです。それぞれの理由は次のとおりです。

・https://kakuyomu.jp/my/works/*
　カクヨムの作品管理の画面（ご本人しか開けない）から、ご自分の作品の読者の反応の数を読んで記録するためと、話の作成画面（/my/works/作品ID/episodes/new）で原稿を題と本文の欄へ入れるため。
・https://kakuyomu.jp/works/*/accesses
・https://kakuyomu.jp/works/*/accesses?*
　カクヨムのアクセス数の画面から、話ごとのPVを読むため。2ページ目以降（?page=2 など）もあるので2つ書いています。どなたの作品でも開ける画面なので、作者が「覚える」を選んだ作品だけを記録します。
・https://www.alphapolis.co.jp/mypage/novel/save_episode/*
　アルファポリスの新しい話の投稿画面で、原稿を題と本文の欄へ入れるため。この範囲は話の編集画面（作品IDのあとに話の番号が続く URL）も含みますが、欄を埋めるのは新しい話の投稿画面と判定できたページだけで、それ以外のページでは何も読まず何も書きません。
・https://www.alphapolis.co.jp/mypage/content
・https://www.alphapolis.co.jp/mypage/content?*
・https://www.alphapolis.co.jp/mypage/content/detail/*
・https://www.alphapolis.co.jp/mypage/novel/save/*
　アルファポリスのマイページ（ご本人しか開けない画面）の作品管理の一覧・作品の管理画面・作品の設定の画面から、ご自分の作品の読者の反応の数（ポイント・お気に入り数・話ごとのいいねなど）と、タグ・連載の状態を読んで記録するため。作品の設定の画面では欄の値を読むだけで、書き換えも保存もしません。ここへ入るのは読者の反応を読む部分だけで、原稿を入れる部分は入りません。
・https://db.narou.fun/novels/*
　小説家になろうの分析サイト「なろうファンDB」の作品のページから、ご自分の作品の読者の反応の数を読むため。どなたの作品でも開ける画面なので、作者が「覚える」を選んだ作品だけを記録します。
・https://kakuyomu.jp/rankings/*
・https://www.alphapolis.co.jp/novel/ranking/*
　カクヨム・アルファポリスのランキングの画面（誰でも見られるページ）。ご自分の作品として覚えた作品が載っていれば、その作品の順位と作品名だけを読み、アイコンの吹き出しでお祝いし、統合小説執筆環境へ渡せるように記録します。並んでいるほかの方の作品は、リンクの行き先（作品ID）を照合のために見るだけで、順位も作品名も読まず、保存しません。覚えた作品が無いサイトでは、ページに触れません。承認したページの種類だけ、開いたときに読みます（初めて開いたときにお尋ねします）。小説家になろう（syosetu.com）と なろうファンDB のランキングには入りません。
・https://creative-story.net/bungakusyou/
・https://creative-story.net/bungakusyou/?*
・https://creative-story.net/202111contest/
・https://creative-story.net/202111contest/?*
・https://tsukuritemirai.com/kobo/novel/
・https://tsukuritemirai.com/kobo/novel/?*
　公募（文学賞・コンテスト）の一覧のページ。作者がアイコンを押したとき、並んでいる公募の名前・締切・字数などと公式サイトへのリンクを読み、VS Code の拡張機能「統合小説執筆環境」で応募先を選べるようにクリップボードへ置きます。誰でも見られるページです。承認したページの種類だけ、開いたときに読みます（承認は設定で取り消せます）——初めて開いたときに「開いたときに自動で取得しますか？」とお尋ねし、「自動で取得する」と答えたときだけ、開いたときに読んで、この拡張の中にページごとに最新の1つだけ残します。ツクリテミライはページ送りがあるので、?page=2 なども書いています。

```

根拠：`manifest.json` の `content_scripts[0].matches`（投稿サイト）と `content_scripts[1].matches`（アルファポリスのマイページ。読み取り係だけ。0.17.0）と `content_scripts[2].matches`（公募の一覧）と `content_scripts[4].matches`（ランキングの画面。読み取り係だけ。0.19.0）、`content/sites.js`（貼り込み先）、`content/statsSites.js`（読む画面・ランキングの画面の表 `RANKING_SITES`）、`content/read.js` の `readRankings`（覚えた作品の行だけを読む）、`content/contestSites.js`（公募の一覧のページ）、`common/guard.js`（ログイン画面の検知）

## リモートコードの使用（Are you using remote code?）

答え：**いいえ（No, I am not using remote code）**

```
この拡張が実行する JavaScript は、すべて拡張のパッケージに入っているファイルです（background.js、offscreen.js、options.js、bubble.js、common/・content/ の各ファイル）。外部のスクリプト・モジュール・WebAssembly を読み込まず、eval や new Function のように文字列からコードを作って実行することもしません。拡張のページ（options.html・offscreen.html・bubble.html）が読み込むのも、パッケージ内のファイルだけです。
```

根拠：
- `options.html` は `options.css` と `options.js`、`offscreen.html` は `offscreen.js`、`bubble.html`（0.14.0。アイコンの吹き出し）は `bubble.css` と `common/messages.js` と `common/rankings.js`（0.19.0）と `bubble.js` だけを読み込む（お祝いの風船・花火は CSS の図形だけで、画像も読み込まない）（外を指すのは Marketplace へのふつうのリンク1本で、スクリプトではない）
- `background.js` の `importScripts` はパッケージ内の `common/`・`content/` のファイルだけ
- `test/redLine.test.js` の「HTTPを発する呼び出しが1つも無い」「文字列からコードを作って実行するコードが1つも無い」「ページへコードを注入する仕組みを使っていない」

## データの利用（Data usage）

### どの種類のデータを扱うか（チェックの案）

Chrome ウェブストアの決まりでは、**送らずにパソコンの中だけで扱うデータも開示の対象**です。この拡張は通信しませんが、保存はするので、次のとおり答えます。

| 種類 | 案 | 理由（コードの根拠） |
|---|---|---|
| 個人を特定できる情報（Personally identifiable information） | **チェックしない** | 名前・住所・メールアドレス・電話番号・ID番号を読まない。保存するのはサイトの種類と作品ID（作品を指す番号で、人を指すものではない）と作品名（覚えた作品の題。0.13.1）と数だけ（`common/stash.js` の `rememberOwnWork`、`common/history.js` の記録の形） |
| 健康に関する情報（Health information） | チェックしない | 扱わない |
| 財務情報と支払い情報（Financial and payment information） | チェックしない | 扱わない |
| 認証情報（Authentication information） | チェックしない | パスワード欄のあるページでは降りる（`common/guard.js` の `isLoginLikePage`）。入力欄の値は読まない（`content/fill.js` の `collectInputDescriptors`・`content/read.js` の `入力欄の素性` が写すのは type と autocomplete と見えているかだけ）。Cookie に触れない（`test/redLine.test.js`） |
| 個人的なコミュニケーション（Personal communications） | チェックしない | コメント・レビューの文章は読まない。数だけ（`content/statsSites.js` の `metric`、長い文字は `MAX_LABEL_TEXT` で落とす） |
| 位置情報（Location） | チェックしない | 扱わない |
| ウェブ履歴（Web history） | **チェックする**（作者の裁定 2026-10-11「申告する」。下の「迷うところ」） | ページのURL・題・訪れた日時の一覧は保存しない。保存するのは覚えた作品の作品IDと作品名（作品ごとにいちばん新しい1つだけ。0.13.1）と、数を読んだ日時だけ（`common/stash.js` の `makeItem` は URL を入れず、ページ番号だけ。作品名は `common/history.js` の `rememberTitle` が覚えた作品の記録に添え、0.13.3 からは統合小説執筆環境へ渡す読者の反応のデータ（`content/read.js` の `封筒`）にも任意の欄 `title` として添える） |
| ユーザーのアクティビティ（User activity） | チェックしない | クリック・キー入力・スクロールを記録しない。ページを見張らない（`test/redLine.test.js` の「ページを見張らない」） |
| ウェブサイトのコンテンツ（Website content） | **チェックする** | 管理画面（カクヨムの作品管理・アクセス数、アルファポリスのマイページの作品管理の一覧・作品の管理画面・作品の設定の画面〔0.17.0〕）・なろうファンDB のページに出ている読者の反応の数（PV・ブックマーク・評価・ポイント・お気に入り・いいねなど）と、その作品の作品名（0.13.1。集計の見出しに使い、0.13.3 からは統合小説執筆環境へ渡すデータにも添える）・タグと連載の状態（0.16.0。同じ）を読んで保存する（`content/read.js` の `readStats`、`background.js` の `記録に残す`）。話の作成画面では、クリップボードの原稿をページの欄へ入れる（保存しない）。公募の一覧のページでは、押したときに公募の文を読んでクリップボードへ置く（`content/contestRead.js` の `readContests`）。0.14.0 から、「開いたときに自動で取得する」と答えたときだけ、開いたときにも読んでページごとに最新の1つを保存する（`background.js` の `棚に置く`、`common/autoRead.js` の `putShelf`）。0.19.0 から、ランキングの画面で覚えた作品の順位と作品名を読んで保存する（`content/read.js` の `readRankings`、`common/stash.js` の `putRankings`。ほかの方の作品は読まない） |

### 迷うところ（作者の判断）

- **ウェブ履歴**：保存している「作品ID＋数を読んだ日時」を、「どのページをいつ開いたか」と読む審査もありえます。
  より安全に倒すなら、これもチェックしてかまいません（チェックしても、下の3つの約束は同じく守れます）
- **個人を特定できる情報**：カクヨムの作品ID・なろうの Nコードは公開されている作品の番号で、たどれば作者の筆名に行き着きます。
  ただし保存するのは作者ご本人が「自分の作品」とした番号だけで、他人の情報ではありません。チェックしない案にしています

### 3つの約束（すべてチェックする）

- 承認されている用途以外で、ユーザーデータを第三者に販売または転送しない
  → 通信しないので、転送する道がない（`test/redLine.test.js` の「HTTPを発する呼び出しが1つも無い」）
- 拡張機能の単一用途と関係のない目的で、ユーザーデータを使用または転送しない
  → 保存した数は、説明のページの集計と、作者が押したときの統合小説執筆環境への受け渡しにだけ使う
- 信用度の判断や融資の目的で、ユーザーデータを使用または転送しない
  → 使わない
