# 貼り込み係（novel-post-helper）

VSCode拡張「統合小説執筆環境（novel-ai-assistant）」の相棒となる Chrome 拡張（Manifest V3）です。
母艦（VSCode側）でコピーした原稿を、**作者が自分で開いた投稿画面の欄へ入れる**道具です。
0.2.0 から、**自分の管理画面に出ている読者の反応（PV・フォロワー・星・応援…）をコピーして
母艦へ戻す**こともできます。

> ## ⚠ いまの状態：テスト中
>
> - **カクヨムの投稿画面の欄は、2026-09-22 に実機で確かめました**（`form#episode-editForm`、
>   `#episodeTitle-input`、`#episodeBody-input`）。本文欄は `textarea` なので、改行はそのまま入ります
> - **カクヨムの読者の反応の読み取りは、2026-09-22 に実機で押しました。** 作品管理の画面から
>   コピーでき、母艦の台帳へ3件（★1,612／今日のPV 1／今月のPV 667）入りました。ただし
>   このとき**「読者からの反応」6欄のうち★しか取れなかった**ので、0.2.1 で正確な数
>   （数字にマウスを当てたときに出る数）から読むよう直しました。**この直しを押し直しての確認は、まだです**
> - **アクセス数の画面は50話ずつのページ送りです**（219話の作品で5ページ）。1回のコピーで入るのは
>   その画面に出ている50話ぶんだけなので、次のページがあるときは「このページの分だけです」と出ます（0.2.2）。
>   ページごとにコピー→取り込みを繰り返してください（母艦は追記するので、二重にはなりません）
> - **アルファポリスは、投稿も読み取りも実機未確認です。** 欄の指定は推測のままで、
>   読み取りは表に枠だけ置いて止めてあります
>
> 欄や数字が見つからないときは「ページの形が変わったようです」と言って**何もしません**ので、
> 書きかけの原稿が壊れることも、読んでいない数字が母艦へ渡ることもありません。実機で確かめたら、
> [`content/sites.js`](content/sites.js)（貼り込み）と [`content/statsSites.js`](content/statsSites.js)（読み取り）の
> 表——**指定はこの2か所だけ**——を直してください。
>
> 確かめが要ることは、この README の末尾「実機で確かめること」に並べてあります。

## 越えない一線

母艦の「サイトへHTTPを1行も書かない」（設計書6.68）と同じ思想です。**約束ではなく、コードで守ります**
（`test/redLine.test.js` がソースを走査して、下の3つを毎回確かめます）。

1. **通信を1本もしません。** `fetch`・`XMLHttpRequest`・`WebSocket`・ビーコンのたぐいを1行も書いていません。
   動くのは、作者が自分で開いたページの中だけです
2. **投稿ボタンを絶対に押しません。** クリックや送信を起こすコードがありません。欄を埋めたところで終わりで、
   内容を確かめて投稿するのは作者です（なろうの規約が明確に禁じるのは、この「自動投稿」です）
3. **認証情報に触れません。** パスワード欄のあるページでは、欄を探す前に降ります（「ログイン画面では動きません」）。
   Cookie もセッションも読み書きしません。ログインは、いつもどおりブラウザで作者が行ってください
4. **読むのは、ご自分の管理画面に出ている「ラベルと数の組」だけです**（設計書6.79.7の枠）。
   貼り込みのときに見るのは「埋める欄が在るか」「その欄が空か」だけ。読み取りのときも、
   本文・他の方の作品・ページ全体の文字は読みません（読む文字には長さの上限を掛けてあります）。
   集めてよいのは [`content/read.js`](content/read.js) だけで、**読んだものの行き先はクリップボードだけ**です
   ——どこにも保存せず、どこへも送りません。対応するのはカクヨムだけで、なろう・pixiv・ハーメルン・note
   では読み取りを行いません（アルファポリスは規約上は可ですが、画面を実機で確かめるまで止めてあります）
5. **開いただけでは動きません。** ポップアップのボタンを押したときに、1回だけ動きます。
   ページを見張る仕組み（MutationObserver・setInterval）は1行もありません

### 権限（できるだけ少なく）

| 権限 | 何のために |
|---|---|
| `clipboardRead` | 母艦がコピーしたデータを読むため |
| `clipboardWrite` | 読んだ読者の反応を、母艦へ渡すためにクリップボードへ置くため（0.2.0で追加） |
| `activeTab` | いま開いているタブのURLを見て、貼り込み先・読み取り先が合っているか確かめるため |
| `content_scripts` の `matches` | カクヨムの投稿まわり・管理画面と、アルファポリスの投稿まわりのページにだけ入るため |

`host_permissions` は**書いていません**。ページへ入る範囲は `manifest.json` の `content_scripts.matches`
だけが決めており、そこに書いていないサイトでは、この拡張は存在しないのと同じです。

## 導入のしかた（開発者モードで読み込む）

ストアには出していません。手元のフォルダーをそのまま読み込みます（ビルドは要りません）。

1. Chrome で `chrome://extensions` を開く
2. 右上の **「デベロッパー モード」** をオンにする
3. **「パッケージ化されていない拡張機能を読み込む」** を押し、このフォルダー（`novel-post-helper`）を選ぶ
4. ツールバーに「貼り込み係」が出る（見当たらなければ、パズルのかけらの印から固定する）

**直したあとは、`chrome://extensions` の再読み込みボタンを押し、投稿ページも再読み込みしてください。**
ページ側のスクリプトは、ページを開いたときに入るためです。

## 使い方の流れ

### その1　原稿を投稿画面へ入れる

1. **母艦（VSCode）** で、投稿する話を開き、投稿キットの **「貼り込み係へ渡す形でコピー」** を実行する
2. **ブラウザ** で、その作品の**話の新規作成画面**を開く（ログインは普通に済ませておく）
3. ツールバーの **「貼り込み係」** を押し、**「この画面に貼り込む」** を押す
4. タイトルと本文が入る。**内容を自分の目で確かめて、投稿ボタンは自分で押す**

途中で止まったときは、理由がそのまま出ます。

| 出る文 | 意味 |
|---|---|
| クリップボードに貼り込み用のデータがありません | 母艦でのコピーがまだ／別のものをコピーした |
| この画面は◯◯の投稿画面ではないようです | サイトが違う（封筒はカクヨム宛て、開いているのは別サイト等） |
| この画面は作品「…」の投稿画面ではないようです | **別の作品**の投稿画面を開いている（複数タブのときに起きる） |
| ◯◯の話の作成画面ではないようです | 作品の管理画面など、欄のないページを開いている |
| ログイン画面では動きません | セッションが切れている。ログインし直してから |
| ページの形が変わったようです | サイトのHTMLが変わり、欄を見つけられない（`content/sites.js` を直す） |

貼り込む前に確認を出すのは、次の2つのときです。断れば何もしません。

- **欄にすでに文が入っている**とき（書きかけの前書きを黙って消さないため）
- **その欄が「見当を付けた欄」だった**とき。`#body` や `contenteditable` のような、
  どのページにもあり得る形で当たった場合は、投稿の欄でない恐れがあるので、空でも一度お尋ねします
  （サイト固有の形——`textarea[name="body"]` など——で当たり、かつ空のときだけ、黙って入れます）

どの欄へ入れたのかは、結果の表示に `本文欄（textarea#episode-body）` の形で出ます。
見覚えのない欄の名前が出たら、貼り込み先が違っている合図です。

### その2　読者の反応を母艦へ戻す（0.2.0から。いまはカクヨムだけ）

1. **ブラウザ** で、次のどちらかの画面を開く（ご自分の作品の画面です）
   - **作品管理**：`https://kakuyomu.jp/my/works/{作品ID}` … 作品全体の反応と、今日・今月のPV
   - **アクセス数**：`https://kakuyomu.jp/works/{作品ID}/accesses` … 話ごとのPVと応援数。
     **50話ずつのページ送り**です（219話の作品で5ページ）
2. ツールバーの **「貼り込み係」** を押し、**「この画面の読者の反応をコピーする」** を押す
3. 「読者の反応 N件（作品全体 1・話 15）をコピーしました」と出る
4. **母艦（VSCode）** の作品管理メニューで **「読者の反応を貼り付けて取り込む」** を実行する

読むのは**そのとき画面に出ている数だけ**です。月を切り替えたり、次のページへ進んだりは
しません（別の期間が欲しいときは、ご自分で画面を切り替えて、もう一度押してください）。

**アクセス数のページに「次へ」があるときは、そう出ます**（0.2.2から）。1〜3の手順を
ページごとに繰り返してください——母艦の取り込みは追記なので、**繰り返しても二重にはなりません**。

| 出る文 | 意味 |
|---|---|
| このページの分だけです。「次へ」で次のページを開き… | 話が50話を超えていて、次のページがある |
| この画面は、読者の反応を読める管理画面ではありません | 上の2つの画面ではない（話の編集画面や公開ページなど） |
| このサイトの読者の反応には対応していません | カクヨム以外のタブを開いている |
| アルファポリスの読者の反応の読み取りには、まだ対応していません | 管理画面の形を実機で確かめられていないため止めてある |
| ページの形が変わったようです | 数字が1つも見つからない（`content/statsSites.js` を直す） |
| ログイン画面では動きません | セッションが切れている |

読めなかった欄は、**0ではなく「欄ごと無し」**で渡します（実機の「応援コメント –」がこれです）。
0と書いてしまうと、母艦の記録に「読んでいない数字」が残り、あとから見分けられなくなるためです。

### クリップボードについて（正直に書きます）

Windows の「クリップボードの履歴」「デバイス間の同期」を有効にしていると、コピーした本文が
Microsoft のクラウドを経由することがあります。これは母艦の「投稿サイト用に変換してコピー」でも同じですが、
未公開のまま取りやめる本文も通りうる、ということは知っておいてください。

## 受け渡しの形（封筒）

母艦とこの拡張が、クリップボード越しにやりとりする JSON です（設計書6.79.3）。

```json
{
  "novelai-post": 1,
  "site": "kakuyomu",
  "workId": "16816927859000000000",
  "title": "第13話 星の落ちる夜",
  "body": "（変換済みの本文）"
}
```

- `novelai-post` は版。**1でなければ読みません**（知らない版を推測で読むと、欄の意味が変わっていたときに
  本文を取り違えて入れることになるため）
- `site` は `kakuyomu` / `narou` / `alphapolis`
- `workId` は任意。**あれば、投稿画面のURLの作品IDと突き合わせます**（複数作品の取り違え防止）。
  ただし**アルファポリスでは、いまは突き合わせません**——URL上の作品IDの形が実機で確かめられておらず、
  当てずっぽうの照合が「たまたま一致」すると、確かめた顔で別の作品へ貼り込むことになるためです。
  この場合は結果の先頭に【…ご自分で確かめてください】と出ます
- `title` は空でも構いません（空なら、タイトル欄は触りません）
- `body` は50万字まで。それを超えるものは、母艦側の取り違え（作品まるごと等）とみなして断ります
- **知らない欄は無視して読みます。** 母艦が将来 `caption` などを足しても、古い貼り込み係が壊れません

### 読者の反応の封筒（向きが逆。拡張 → 母艦）

こちらは、この拡張が作って**クリップボードへ置く**JSONです（設計書6.79.7）。母艦の
`core/readerStatsEnvelope.ts` が受けます。

```json
{
  "novelai-stats": 1,
  "site": "kakuyomu",
  "workId": "16816927859000000000",
  "readAt": "2026-09-22T01:00:00.000Z",
  "entries": [
    { "scope": "work", "metrics": { "bookmarks": 23, "pv": 1269, "points": 18, "reviews": 6, "likes": 33 } },
    { "scope": "work", "period": "day", "periodKey": "2026-09-22", "metrics": { "pv": 0 } },
    { "scope": "work", "period": "month", "periodKey": "2026-09", "metrics": { "pv": 2 } },
    { "scope": "episode", "episode": 1, "metrics": { "likes": 4, "pv": 102 } }
  ]
}
```

- `readAt` は**読んだ時刻**です（取り込んだ時刻ではありません）
- `workId` はURLから読んだ作品IDです。母艦はこれを台帳と突き合わせ、**別の作品の画面を開いたまま
  押したとき**に取り込みを止めます
- カクヨムの表示を母艦の欄へ写す対応は、フォロワー→`bookmarks`、PV→`pv`、★の数→`points`、
  レビュー→`reviews`、応援→`likes`、応援コメント→`comments` です
- **「読者からの反応」の6欄（フォロワー・PV・★・レビュー・応援・コメント）は、数字にマウスを
  当てたときに出る正確な数から読みます**（0.2.1から）。画面の表示が `1.05M`・`27.5K` のように
  省略されていても、`1,053,339`・`27,534` が入ります。正確な数がどこにも無いときは、その欄を入れません
- **今週は読みません。** 母艦の粒度は日・月・年・累計で、週がありません。無い粒度を
  月や日に寄せると、あとから見て何の数字か分からなくなります
- 読めなかった欄は入れません（`0` を書きません）

## 各サイトの規約について（要旨）

2026-09-05に各サイトの利用規約の原文を確かめた結果です（設計書6.79.1が正、ここは要旨）。

| サイト | 判定 |
|---|---|
| **カクヨム** | 自動化・収集を禁じる条文がなく、負荷も妨害も生まない貼り込みは**問題なし**。第1弾で対応 |
| **アルファポリス** | 同じく明示条文なし。**問題なし**。第1弾で対応 |
| **小説家になろう** | 第14条23号が「APIを使う以外の**自動化された手段でのアクセス・データ収集**」を禁止。
貼り込み（欄を埋めるだけ）は文言上その対象外と読めますが、**4サイトで最も厳しい書きぶり**で、
**送信の自動化は明確に一線を越えます**。表に枠だけ置き、**貼り込みは行いません**。
読み取り（アクセス解析の取り込み）は**対応しない**と決めています |
| **note** | 規約本文が機械取得を拒む（403）ため原文未確認。人の目で確かめるまで対応しません |
| **pixiv小説・ハーメルン** | 「機械的な操作」「ツール使用」の語があり**グレー**。対応するかは作者の最終判断 |

この拡張が「自動化されたアクセス」に当たらないと考える理由は、**サーバーへ何も送らない**からです。
ページを開くのも、投稿ボタンを押すのも、作者本人の操作です。

## 中身の構成

```
novel-post-helper/
├─ manifest.json      権限と、入るページの範囲
├─ popup.html/.css/.js  ボタンの画面。クリップボードを読み、照合し、ページへ依頼する
├─ common/            画面にもページにも依存しない、素の判定（テストがあるのはここ）
│  ├─ envelope.js     封筒の検証（版・サイト・題・本文・作品ID）
│  ├─ match.js        貼り込み先の照合（ドメイン・作成画面か・作品ID）
│  ├─ guard.js        ログイン画面の検知、書き込んでよい欄かの判定
│  └─ messages.js     日本語の文言（1か所にまとめる）
├─ content/
│  ├─ sites.js        ★貼り込みの欄の指定。**直すのはここだけ**
│  ├─ statsSites.js   ★読み取りの表（どのページを・どう読むか）。**直すのはここだけ**
│  ├─ fill.js         ページの欄を埋める場所（送信はしない）
│  └─ read.js         唯一、管理画面の数字を読む場所（ページには1文字も書かない）
└─ test/              vitest。DOM操作そのものは対象外（実機の領分）
```

`common/` と `content/sites.js` は、ポップアップとページ側の**両方が同じファイルを読みます**
（写しを作らないため）。ビルド工程はありません——読み込んで、そのまま動きます。

### テスト

```powershell
npm install
npm test
```

`test/redLine.test.js` は、ソースを走査して「通信のコードが無いこと」「送信のコードが無いこと」
「Cookie に触れていないこと」「文字列からコードを作っていないこと」「HTMLを組み立てて差し込んで
いないこと」「ページへコードを注入していないこと」「ページと窓越しにやり取りしていないこと」
「権限が増えていないこと」を毎回確かめます。

0.2.0 で読み取りを足したので、「ページから集めない」の見張りも足しました——**封筒を組み立てるのは
`content/read.js` だけ**／**ページの文字を読むのは読み取り係と貼り込み係だけ**／**読んだものの
行き先はクリップボードだけ**（保存の口を使わない）／**ページを見張らない**。
ここに3つ目のファイルが増えたら、それは一線の引き直しです。

`test/readEnvelope.test.js` は、母艦（`novel-ai-assistant`）がこのフォルダーの隣にあるときだけ、
**母艦の本物の読み口**（`core/readerStatsEnvelope.ts`）に封筒を食わせて確かめます。
封筒は2つのプロジェクトの約束事なので、検証を写すのではなく、相手に直接読ませています
（母艦が無い環境では、その組だけ飛ばします）。

走査するファイルは**その場でフォルダーを辿って集めます**（`node_modules`・`test`・`.git` 以外の
すべて）。手で書いた一覧にすると、新しく足したファイルが検査されないまま通ってしまうためです。
**走査そのものが働いているか**——新しいファイルを拾うか、禁止の書き方を本当に見つけられるか——も、
架空のソースを食わせて同時に確かめています。
