# 統合小説執筆環境ヘルパー（novel-post-helper）

小説を書く方のための Chrome 拡張（Manifest V3）です。

**この拡張だけで使えます（0.10.0）。** ご自分の作品の読者の反応（PV・ブックマーク・評価など）を、
管理画面を開いたときに拡張の中へ記録し、作品ごとに**いまの数・日ごとの推移・離脱率／ブックマーク率／評価率**を
説明のページで簡単に集計します。使い方は「ご自分の作品の管理画面を開く → 作品を覚える → 集計を見る」の3つだけです
（下の「その0」）。グラフ・作品の事情を踏まえたAIの助言・原稿との突き合わせなど、詳しい分析は
VS Code の拡張機能 [「統合小説執筆環境」](https://marketplace.visualstudio.com/items?itemName=nonahisa.novel-ai-assistant)
（novel-ai-assistant）でできます。

**統合小説執筆環境をお使いの方は、説明のページの「統合小説執筆環境へ渡す」を入れてください（0.11.0）。**
新しく入れたときは切ってあり、切っている間はアイコンを押すと集計が開きます（VS Code は呼び出しません。
話の作成画面では、切っていても貼り込みます。0.11.1）。
0.10.0 以前から更新した方は、入ったままです。

統合小説執筆環境をお使いの方は、この拡張を**相棒**としても使えます。
統合小説執筆環境でコピーした原稿を、**作者が自分で開いた投稿画面の欄へ入れる**道具です。
0.2.0 から、**自分の管理画面に出ている読者の反応（PV・フォロワー・星・応援…）をコピーして
統合小説執筆環境へ戻す**こともできます。0.6.0 から、なろうの作品は**ご自分の作品の Narou.fun のページ**
（なろうの分析サイト `db.narou.fun`）からも読めます。

0.8.0 で名前を「貼り込み係」から **「統合小説執筆環境ヘルパー」** に改め、ポップアップを無くしました。
**ツールバーのアイコンを押すか、ページの上で右クリックして項目を選ぶだけで、いまの画面でできることを1つ実行します。**
使える画面ではアイコンに印（**貼**＝貼り込める、**読**＝読者の反応を読める）が付き、押した結果は Chrome のお知らせで出ます。

0.9.0 から、**読者の反応は、ご自分の作品の画面を開いたときに自動で拡張の中へ溜め、押したときにまとめて1回で渡します**
（アイコンの印は「読3」のように、溜まっている画面の数）。**ほかの方の作品は溜めません**——どなたの作品でも開ける画面
（Narou.fun・カクヨムのアクセス数）では、「ご自分の作品として覚える」を選んだ作品だけを溜めます。

0.12.0 から、**公募（文学賞・コンテスト）の一覧のページで押すと、並んでいる公募をまとめて統合小説執筆環境へ渡せます**
（アイコンの印は **募**）。統合小説執筆環境の「作品目標設定」で、応募先に選べます（下の「その3」）。

0.13.0 から、**カクヨムの作品管理の画面で右クリック →「章立てを取得」を選ぶと、大見出しと話の並びを
統合小説執筆環境へ渡せます。** カクヨムのバックアップには章が入っていないためです（下の「その4」）。

0.13.1 から、**読者の反応の集計の見出しに、作品IDではなく作品名が出ます**（作品IDは括弧で添えます）。
作品名は、その作品の画面（カクヨムの作品管理・アクセス数、Narou.fun の作品のページ）を開いたときに覚えます。
まだ覚えていない作品は、これまでどおり作品IDで出ます。

0.13.2 から、渡したときの知らせに「**VS Code が前に出なければ、もう一度押してください**」（章立ては「もう一度選んでください」）と添えます。

0.13.3 から、**右クリックの項目を「読者の反応を取得」「章立てを取得」「公募一覧を取得」「本文を貼り込み」のように、
何をするかが頭に来る短い名にそろえました**（アイコンに重ねたときの説明は、これまでどおりの言い方です）。
統合小説執筆環境へ渡す読者の反応には、読めたときは作品名（`title`）も添えます。

0.14.0 から、**取得できる画面（カクヨムの作品管理・アクセス数、Narou.fun の作品ページ、公募の一覧）を初めて開いたとき、
「開いたときに自動で取得しますか？」とお尋ねします**（画面の種類ごとに1回だけ）。「自動で取得する」と答えた種類の画面は、
開いたときに取得して、ツールバーのアイコンの吹き出しで「取得しました（溜まり N画面）」とお知らせします
（吹き出しを出せないときは Chrome のお知らせ）。統合小説執筆環境へ渡すのは、これまでどおりアイコンを押したときです。

0.14.1 から、「取得しました」の吹き出しに、字の無いボタンが2つ出ていたのを直しました。
答えは説明のページの「開いたときの自動取得」で後から変えられます。0.13.x から更新した方は、読者の反応の画面は「自動」のまま始まります。

0.14.2 から、**アルファポリスの新しい話の投稿画面（`www.alphapolis.co.jp/mypage/novel/save_episode/{作品ID}`）で貼り込めます**
（題と本文。話の編集画面には入れません）。**2026-11-01 にリニューアルしたなろうファンDB（Narou.fun）の作品ページ
（`db.narou.fun/novels/{Nコード}`）も読めます**（日ごとの表は、全期間＝直近30日を毎回読みます）。
説明のページに、統合小説執筆環境の Open VSX のページへのリンクも並べました。

0.15.0 から、**アルファポリスへ貼り込むとき、統合小説執筆環境から渡された章の名前と同じ章を、章の欄で選びます**。

0.16.0 から、**作品のタグと、連載中か完結かも読みます**（カクヨムの作品管理、なろうファンDB の作品ページ）。
集計の見出しの下に出て、統合小説執筆環境へ渡すデータにも入ります。集計の見出しは、長い題でも折り返して全部出ます。

0.17.0 から、**アルファポリスの読者の反応も読みます**。マイページの作品管理の一覧（作品ごとの累計ポイント・24時間のポイント・
お気に入り数・ハート）、作品の管理画面（話ごとのいいね・しおり・エール・誤字報告）、作品の設定の画面（タグと連載の状態。欄は書き換えません）です。
どれもご自分しか開けない画面なので、開いて読めた作品はご自分の作品として覚えます。開いたときに自動で取得するかは、初めて開いたときにお尋ねします。

0.19.0 から、**カクヨム・アルファポリスのランキングの画面に、ご自分の作品が載っていたらお祝いします**。
ツールバーのアイコンの吹き出しで「〈作品名〉が〈ランキングの名前〉で N 位に入っています。おめでとうございます！」と出し、
初めて入った・順位が上がったときは風船、10位以内や大きく上がったときは花火、1位は大きな花火が上がります
（前に見たときより下がった・同じときは文だけ。パソコンの「動きを減らす」設定のときも文だけ）。
順位は記録して、統合小説執筆環境へ渡すデータに入ります。読むのはご自分の作品として覚えた作品の順位だけで、ほかの方の作品の順位や作品名は読みません。
開いたときに自動で読むかは、初めて開いたときにお尋ねします。押したときは、その場で読みます。小説家になろうのランキングでは何もしません。

## この拡張がしないこと

統合小説執筆環境の「サイトへHTTPを1行も書かない」（設計書6.68）と同じ思想です。**約束ではなく、コードで守ります**
（しないことを見張るテスト `test/redLine.test.js` がプログラムの中身を調べて、下のことを毎回確かめます）。

1. **通信を1本もしません。** `fetch`・`XMLHttpRequest`・`WebSocket`・ビーコンのたぐいを1行も書いていません。
   動くのは、作者が自分で開いたページの中だけです。
   読者の反応を渡したあとに VS Code を呼び出しますが（0.8.0）、これは**お手元の VS Code を
   `vscode://` のリンクで前に出すだけ**で、どこのサーバーへも何も送りません。リンクにはデータを載せず、
   読者の反応はクリップボードで渡します。
   **読者の反応を溜める場所（0.9.0）は、この拡張の中の保存（`chrome.storage.local`）だけです。**
   Chrome が拡張ごとにパソコンの中に持つ保存場所で、**通信ではありません**。Google のアカウントで別のパソコンへ
   同期する保存（`chrome.storage.sync`）は使いません（使うと送ることになるため。テストが見張ります）。
   **集計のための記録（0.10.0）も同じ保存場所だけ**で、集計の計算も表と棒も拡張の中で組みます
   （外のライブラリや字体を読み込みません）。
   **説明のページには、統合小説執筆環境の Marketplace のページへのリンクが1本だけあります（0.10.0）。**
   押したときにだけブラウザが新しいタブで開くふつうのリンクで、この拡張がデータを送るのではありません
   （リンクは固定の文字で作品IDや数を載せず、どのページから来たかも渡しません）。外を指すのはこの1本だけで、
   テストが見張ります
2. **投稿ボタンを絶対に押しません。** クリックや送信を起こすコードがありません。欄を埋めたところで終わりで、
   内容を確かめて投稿するのは作者です（なろうの規約が明確に禁じるのは、この「自動投稿」です）
3. **認証情報に触れません。** パスワード欄のあるページでは、欄を探す前に降ります（「ログイン画面では動きません」）。
   Cookie もセッションも読み書きしません。ログインは、いつもどおりブラウザで作者が行ってください
4. **読むのは、ご自分の管理画面と、ご自分の作品の Narou.fun のページに出ている「ラベルと数の組」と、作品名・タグ・連載の状態（連載中か完結か。0.16.0）だけです**
   （`docs/設計書.md` 7.1の枠）。貼り込みのときに見るのは「埋める欄が在るか」「その欄が空か」と、アルファポリスの章の選択肢の名前（章を選ぶために比べるだけ。0.15.0）だけ。読み取りのときも、
   本文・他の方の作品・ページ全体の文字は読みません（読む文字には長さの上限を掛けてあります）。
   集めてよいのは [`content/read.js`](content/read.js) だけで、**読んだものの行き先は、拡張の中の溜まり・記録と
   クリップボードだけ**です（0.9.0 から溜まり、0.10.0 から集計のための記録が加わりました）——どこへも送りません。対応するのはカクヨム・アルファポリスの管理画面（0.17.0）と Narou.fun の作品ページだけで、
   **なろう本体（syosetu.com）とそのアクセス解析（KASASAGI）**・pixiv・ハーメルン・note では読み取りを
   行いません。
   **Narou.fun とカクヨムのアクセス数の画面は、どなたの作品のページでも開けます**（カクヨムのアクセス数は、
   ログインしていなくても開けることを 2026-09-23 に確かめました）。この拡張には作者の作品かどうかが分からないので、
   **初めての作品は溜めず、押したときに「ご自分の作品ですか？」とお尋ねし、「覚える」を選んだ作品だけを溜めます**（0.9.0）。
   カクヨムの作品管理はご本人しか開けないので、読んだ作品は自動で覚えます。取り込むときにも、統合小説執筆環境が
   作品ID（Nコード）でご自分の作品かどうかを確かめます。
   **ランキングの画面（0.19.0。カクヨムの `kakuyomu.jp/rankings/*`、アルファポリスの `www.alphapolis.co.jp/novel/ranking/*`）では、
   ご自分の作品として覚えた作品の順位と作品名だけを読みます**——並んでいる作品へのリンクの行き先（作品ID）を見て照合し、

   話の題と大見出しの字を読みます**——ご自分の作品の管理画面（ログインした本人しか開けない）に出ている字で、
   数は読みません。読むのは選んだときの1回だけで、クリップボードへ置くだけ（溜めない）。読むのは
   [`content/chapterRead.js`](content/chapterRead.js) だけです
5. **開いただけでは貼り込みません。** 貼り込みは、アイコンを押すか右クリックの項目を選んだときに、1回だけ動きます。
   **承認したページの種類だけ、開いたときに読みます（承認は設定で取り消せます）**（0.14.0。それまでは、ご自分の作品の
   読者の反応の画面を訊かずに読んでいました）。初めて開いたときに「開いたときに自動で取得しますか？」とお尋ねし、

   「開いたときの自動取得」で変えられます。読者の反応の画面は、承認していても、ご自分の作品として覚えた作品だけを読みます。
   ページを見張る仕組み（MutationObserver・setInterval）は1行もありません。

## 使い方の流れ

**アイコンを押すか、ページの上で右クリックして「本文を貼り込み」「読者の反応を取得」などの項目を選ぶと、いまの画面でできることを
1つだけ実行します**（0.8.0から。それまではポップアップの2つのボタンでした）。1つの画面で両方ができることは無いためです。

| アイコンの印 | 画面 | 押すと | 右クリックの項目 |
|---|---|---|---|
| **貼**（青） | 話の作成画面 | 原稿を題と本文の欄へ入れる | 本文を貼り込み |
| **読3**（緑） | ご自分の作品の作品管理・アクセス数・Narou.fun の作品ページ | この画面を読み直してから、溜まった読者の反応をまとめて渡し、VS Code を呼ぶ（0.9.0。数字は溜まっている画面の数。溜まりが無いときは **読**） | 読者の反応を取得 |
| **?**（橙） | まだ覚えていない作品の Narou.fun のページ・カクヨムのアクセス数 | 「ご自分の作品ですか？」と訊く（0.9.0） | 自分の作品として覚える |
| **募**（紫） | 公募の一覧のページ（ノベルポータルの2ページ・ツクリテミライ） | 並んでいる公募を読んでクリップボードへ置き、VS Code を呼ぶ（0.12.0） | 公募一覧を取得 |
| （**読3** がどの画面にも出る） | それ以外の画面で、溜まりがあるとき | 溜まった読者の反応をまとめて渡し、VS Code を呼ぶ（0.9.0） | 読者の反応を取得（溜めた分）（この拡張の入るページだけ） |
| （無し） | それ以外 | どの画面でなら何ができるかを知らせる | 出ない |

上の表は「統合小説執筆環境へ渡す」を**入れているとき**です。**切っているとき**（新しく入れたときはこちら。0.11.0）は次のとおりです。

| アイコンの印 | 画面 | 押すと | 右クリックの項目 |
|---|---|---|---|
| **読**（緑。数字は付かない） | ご自分の作品の作品管理・アクセス数・Narou.fun の作品ページ | この画面を読み直して記録し、説明のページの集計を開く | 集計を表示 |
| **?**（橙） | まだ覚えていない作品の Narou.fun のページ・カクヨムのアクセス数 | 「ご自分の作品ですか？」と訊く | 自分の作品として覚える |
| **貼**（青） | 話の作成画面 | 原稿を題と本文の欄へ入れる（入れているときと同じ。0.11.1） | 本文を貼り込み |
| **募**（紫） | 公募の一覧のページ | 並んでいる公募を読んでクリップボードへ置く（VS Code は呼ばない。0.12.0） | 公募一覧をコピー |
| （無し） | それ以外 | 説明のページの集計を開く | 出ない |

切っている間は、開いた画面の読者の反応を集計のための記録にだけ残し、統合小説執筆環境へ渡す分（溜まり）には溜めません。
切る前に溜まっていた分は消えません（入れ直せば渡せます）。印は、開いているページを開き直すと切り替わります。

押した結果は、画面の隅に出る **Chrome のお知らせ**で出ます（ページの中には出しません）。お知らせが出ないときは、
Windows の「設定」→「通知」で Google Chrome の通知がオンか確かめてください。
押したあとの確かめ（作品の取り違え・読める管理画面か・ログイン画面か）は、これまでどおり全部そのまま働きます。
印は見た目の親切で、守りではありません——印が古いままでも、間違った場所へは貼り込まれません。

印と右クリックの項目は、**拡張を入れ直したあと、ページを読み直すまで出ません**（ページが開いたときに付けるため）。

### その0　読者の反応を記録して、簡単に集計する（この拡張だけで使えます。0.10.0）

統合小説執筆環境（VS Code）を持っていなくても使えます。

1. **ご自分の作品の管理画面を開く。** カクヨムは作品管理の画面（`kakuyomu.jp/my/works/{作品ID}`）、
   なろうの作品は Narou.fun の作品のページ（`db.narou.fun/novels/{Nコード}`。例：`db.narou.fun/novels/n1234ab`）
2. **作品を覚える。** カクヨムの作品管理はご本人しか開けないので、読めたら自動で覚えます（初めて開いたときの「開いたときに自動で取得しますか？」に「自動で取得する」と答えるか、アイコンを押すと読みます。0.14.0）。
   Narou.fun のページ・カクヨムのアクセス数はどなたの作品でも開けるので、アイコンに **?** が付きます。
   押して「覚える」を選ぶか、説明のページの「ご自分の作品として覚えた作品」に作品ID（Nコード。例：N1234AB）を書いて保存します
3. **集計を見る。** 覚えた作品の画面を開くたびに記録します。アイコンを押す（「統合小説執筆環境へ渡す」を切っているとき）か、
   アイコンを右クリック → **「集計を表示」** で、説明のページの「読者の反応の集計」が開きます

集計に出るもの（覚えた作品ごと）：

| 欄 | 中身 |
|---|---|
| 見出し | 作品名と作品ID（「潮騒の灯台守（作品ID 1177…）」の形。0.13.1）。作品名は画面を開いたときに覚え、まだ覚えていない作品は作品IDだけ。長い題は折り返します（0.16.0） |
| 連載の状態とタグ | 「連載中　タグ：…」の1行（0.16.0）。いちばん新しく読めた画面のもの。タグが無いと分かった作品は「タグ：なし」、まだ読めていない作品には出ません |
| いまの数 | サイトが見せている作品全体の数（カクヨム：PV・フォロワー・★・レビュー・応援・応援コメント／Narou.fun：総合P・ブクマ・評価P・評価者数・レビュー・感想数・週間読者）。今日と今月の数があれば、それも |
| 日ごとの数 | サイトが出している、その日の数（カクヨムの日ごとのPV、Narou.fun の日ごとのブクマと評価Pの増減）。直近14日を、字の棒つきで |
| 記録した日ごとの数 | この拡張が記録した日ごとの作品全体の数と、前の記録からの増え方。記録の間が1日より空いた日は `*` を付けます（その間の合計の増え方なので）。数と増え方は別の列で、数の桁が縦に揃います（0.11.2） |
| 率 | 離脱率・ブックマーク率・評価率。**式と実際の数を並べます** |

**率の式は統合小説執筆環境と同じです**（`src/core/readerRates.ts`）。

- **離脱率** ＝ 1 − 基準の話のPV ÷ 第1話のPV。基準の話は、更新から**読んだ時点までに72時間以上たっていた**話のうち、話数がいちばん大きい話
  （更新した直後の話はまだ読まれ切っていないので、そこで測ると離脱率が高く見える）
- **ブックマーク率** ＝ 作品全体のブックマーク（カクヨムはフォロワー）÷ 第1話のPV
- **評価率** ＝ 評価した人数 ÷ 第1話のPV（カクヨムはレビュー、なろうは評価者数——なろうの「レビュー」は書かれたレビューの件数のため）

材料が欠けたら **0% とは書かず、「出せません：第1話のPVがありません」のように足りない材料を書きます**
（0% と書くと、読めなかったのか本当に0なのか見分けが付かなくなるため）。
話ごとのPVは、カクヨムの作品管理（全話・更新日つき）かアクセス数の画面から読みます。
**Narou.fun には話ごとのPVが無いので、なろうの作品の率は出せません**（それも理由として出ます）。

グラフ・作品の事情を踏まえたAIの助言・原稿との突き合わせなど、詳しい分析は統合小説執筆環境でできます。
集計の下に、[統合小説執筆環境の Marketplace のページ](https://marketplace.visualstudio.com/items?itemName=nonahisa.novel-ai-assistant)
へのリンクがあります（押したときだけ新しいタブで開きます。この拡張がデータを送るのではありません）。

> 下の「その1」「その2」は、**統合小説執筆環境をお使いの方向け**です。「その1」の貼り込みは、
> 説明のページの「統合小説執筆環境へ渡す」の入・切にかかわらず使えます（0.11.1）。「その2」を使うときは、説明のページ
> （アイコンを右クリック →「集計を表示」）の **「統合小説執筆環境へ渡す」** を入れてください（0.11.0）。
> 切っている間は「まとめて渡す」をせず、VS Code も呼び出しません。

### その1　原稿を投稿画面へ入れる（統合小説執筆環境をお使いの方向け）

1. **統合小説執筆環境（VS Code）** で、投稿する話を開き、投稿キットの **ヘルパーへ渡す形のコピー**
   （統合小説執筆環境の表示が「貼り込み係へ渡す形でコピー」のときは、それ）を実行する
2. **ブラウザ** で、その作品の**話の新規作成画面**を開く（ログインは普通に済ませておく）。アイコンに **貼** が付く。
   直した原稿を入れ直すときは、**話の編集画面**でも入れられます（0.20.0・作りかけ。下の「話の編集画面で入れるとき」）
3. ツールバーのアイコンを押す（または、ページの上で右クリックして「本文を貼り込み」）
4. タイトルと本文が入り、「貼り込みました」のお知らせが出る。**内容を自分の目で確かめて、投稿ボタンは自分で押す**
   アルファポリスでは、同じ名前の章が1つだけあれば章も選び、お知らせに「章：◯◯」と出ます（選べなければ「章は選べませんでした」と出るので、章はご自分で選んでください。0.15.0）

途中で止まったときは、理由がそのまま出ます。

| 出る文 | 意味 |
|---|---|
| クリップボードに貼り込み用のデータがありません | 統合小説執筆環境でのコピーがまだ／別のものをコピーした |
| この画面は◯◯の投稿画面ではないようです | サイトが違う（コピーしたデータはカクヨム宛て、開いているのは別サイト等） |
| この画面は作品「…」の投稿画面ではないようです | **別の作品**の投稿画面を開いている（複数タブのときに起きる） |
| ◯◯の話の作成画面ではないようです | 作品の管理画面など、欄のないページを開いている |
| ログイン画面では動きません | セッションが切れている。ログインし直してから |
| ページの形が変わったようです | 入れる欄が見つからなかった。サイトの画面が変わったのかもしれません。ヘルパーを新しくするか、開発者へお知らせください |

貼り込む前に確認を出すのは、次の2つのときです。断れば何もしません。

- **欄にすでに文が入っている**とき（書きかけの前書きを黙って消さないため）
- **その欄が「見当を付けた欄」だった**とき。`#body` や `contenteditable` のような、
  どのページにもあり得る形で当たった場合は、投稿の欄でない恐れがあるので、空でも一度お尋ねします
  （サイト固有の形——`textarea[name="body"]` など——で当たり、かつ空のときだけ、黙って入れます）

どの欄へ入れたのかは、結果の表示に `本文欄（textarea#episode-body）` の形で出ます。
見覚えのない欄の名前が出たら、貼り込み先が違っている合図です。

**話の編集画面で入れるとき（0.20.0・作りかけ）**：カクヨムの `/my/works/{作品ID}/episodes/{話ID}`、アルファポリスの
`/mypage/novel/save_episode/{作品ID}/{話ID}` でも入れられます。保存してある本文を置き換えるので、**欄が空でも空でなくても、
毎回お尋ねします**（「この話の本文（いま N字）を、コピーした本文（M字）に置き換えます。サイトにはまだ保存されません…」）。
画面の題とコピーした題が違うときは、両方を並べてお見せします（別の話の編集画面でないか確かめてください）。
サイトにはまだ保存されないので、やめたいときは［更新］［保存］を押さずにページを読み直せば元に戻ります。
アルファポリスでは、章も新しい話のときと同じように選びます。

### 投稿したあと、話の番号を統合小説執筆環境へ渡す（0.20.0・作りかけ）

1. 投稿／保存を押して、サイトが話の編集画面（なろうは作品・話の管理画面）へ移ったら、ツールバーのアイコンを押す
2. アドレス欄の URL にある**作品ID・話の番号**と、画面の**題の欄の字**（なろうは**小説番号・部分の番号**だけ）を読み、クリップボードへ置いて統合小説執筆環境を呼びます。
   本文は読みません。その作品へ最後に入れた原稿に統合小説執筆環境が付けた札があれば、それも添えます（どの話かを見分けるため）
3. 話の編集画面でアイコンを押したとき、**まだ入れていない原稿がクリップボードにあれば、番号は渡さずに原稿を入れます**。
   一度入れた原稿（投稿したあともクリップボードに残っているもの）か、原稿が無いときに、番号を渡します
4. なろうの画面ではアイコンに印が出ませんが、押せば動きます（この拡張はなろうのページに入らないため）

### その2　読者の反応を統合小説執筆環境へ戻す（統合小説執筆環境をお使いの方向け。0.2.0から。いまはカクヨム・アルファポリス〔0.17.0〕と、なろうの作品の Narou.fun）

**0.9.0 から、開いたら溜まり、押すとまとめて1回で渡します**（作者の依頼「キャッシュして渡すことはできないでしょうか？」）。

1. **ブラウザ** で、ご自分の作品の読者の反応の画面を開く。**開くだけで、その画面の読者の反応が拡張の中へ溜まります**
   （アイコンの印が「読1」「読2」…と増え、吹き出しで「取得しました（溜まり N画面）」と出ます）。いくつもの作品・ページを続けて開いて構いません。
   0.14.0 から、初めて開いた種類の画面では「開いたときに自動で取得しますか？」とお尋ねします。「今までどおり押して取得する」と
   答えた種類の画面は、開いても溜まらず、押したときにその画面を読んで渡します
2. **初めての Narou.fun の作品・カクヨムのアクセス数**では、印が **?** になり、開いても溜まりません。
   アイコンを押すと「ご自分の作品ですか？」と Chrome のお知らせで訊くので、「覚える」を押す（以後はその作品を開くと溜まります）。
   カクヨムは、**作品管理の画面を一度読めば、その作品を自動で覚えます**（作品管理はご本人しか開けないため）
3. 溜まったら、**アイコンを押す**（どの画面でも構いません。読者の反応の画面で押したときは、その画面を読み直してから）。
   溜まった分が1つにまとまってクリップボードへ入り、VS Code が前に出て、統合小説執筆環境が取り込みます
   （「Visual Studio Code を開きますか？」と Chrome が尋ねたら「開く」）
4. 渡すと溜まりは空になります（印が消えます）。統合小説執筆環境が取り込めなかったときは、アイコンを右クリック →
   「オプション」の説明のページで **「もう一度渡す」** を押す（渡した分は、次に渡すまで・長くても7日、控えてあります）

以下は、読める画面と、1つの画面から読むものの説明です（0.8.0 までと同じ）。

1. 読める画面は次のどちらか（ご自分の作品の画面です）。
   **作品管理のほうが、1回で全部入ります**（0.4.0から）

   | | 作品管理 | アクセス数 |
   |---|---|---|
   | URL | `kakuyomu.jp/my/works/{作品ID}` | `kakuyomu.jp/works/{作品ID}/accesses` |
   | 話の数 | **1回で全話** | **50話ずつ**・ページ送り（219話なら5ページ） |
   | 話ごとに読む欄 | 応援・応援コメント・PV | 応援・PV |
   | 作品全体の反応 | 読む（フォロワー・PV・★・レビュー・応援・応援コメント）＋今日と今月のPV | 読まない |
   | 各話の更新日 | 読む（「最終更新」の日時。0.5.0から） | 読まない |
   | 直近の日ごとのPV | 読む（反応のグラフの1本ずつ。0.5.0から） | 読まない |
   | 押す回数 | **1回** | ページの数だけ |

2. その画面で押したときのお知らせには、その画面からの件数も出ます
   （「この画面からは 251件（作品全体 2・日ごと 30・話ごと 219）」。作品全体の2は、反応の6欄と今月のPV）
3. VS Code が前に出ないとき・統合小説執筆環境が古いときは、作品管理メニューの
   **「読者の反応を貼り付けて取り込む」** を実行する（読者の反応はクリップボードに入っています）

読むのは**そのとき画面に出ている数だけ**です。月を切り替えたり、次のページへ進んだりは
しません（別の期間が欲しいときは、ご自分で画面を切り替えて、もう一度押してください）。

**アクセス数のページに「次へ」があるときは、そう出ます**（0.2.2から）。0.9.0 からは、「次へ」で次のページを
開けば、そのページも溜まります（ページごとに別の1件。同じページを開き直すと置き換わるので、**二重にはなりません**）。

| 出る文 | 意味 |
|---|---|
| この画面はこのページの分だけです。「次へ」で次のページを開くと… | 話が50話を超えていて、次のページがある |
| 溜まっている読者の反応がありません | 説明のページで「まとめて渡す」を押したが、溜まりが空（0.9.0） |
| まとめましたが、クリップボードへ置けませんでした | 溜まりは消えていないので、もう一度押せば渡せる（0.9.0） |
| この画面は、読者の反応を読める管理画面ではありません | 上の2つの画面ではない（話の編集画面や公開ページなど） |
| このサイトの読者の反応には対応していません | カクヨム・アルファポリス・Narou.fun 以外のタブを開いている（なろう本体・KASASAGI もここ） |
| ページの形が変わったようです | 数字が1つも見つからなかった。サイトの画面が変わったのかもしれません。ヘルパーを新しくするか、開発者へお知らせください |
| ログイン画面では動きません | セッションが切れている |

読めなかった欄は、**0ではなく「欄ごと無し」**で渡します（実機の「応援コメント –」がこれです）。
0と書いてしまうと、統合小説執筆環境の記録に「読んでいない数字」が残り、あとから見分けられなくなるためです。

#### なろうの作品：Narou.fun の作品ページ（0.6.0から）

なろう本体（syosetu.com）は規約の判断で読みません。代わりに、なろうの分析サイト **Narou.fun** の
**ご自分の作品のページ**（`https://db.narou.fun/novels/{Nコード}`。2026-11-01 のリニューアルで、サイトの名は「なろうファンDB」になりました）から、作品全体の数を読みます。
統合小説執筆環境の執筆量パネル「サイトの記録」の **「分析（Narou.fun）を開く」** で開けるページです。

1. **ブラウザ** で、ご自分の作品の Narou.fun のページを開く。初めての作品なら印が **?** になるので、アイコンを押して「覚える」を選ぶ（0.9.0）
2. アイコン（印は **読1** など）を押す。その画面を読み直して溜め、溜まった分をまとめて渡します（「この画面からは 28件（作品全体 1・日ごと 27）」のように。日ごとの表は、画面で7日・14日・全期間のどれを選んでいても、全期間＝直近30日を読みます）
3. VS Code が前に出て、**統合小説執筆環境** が取り込む（前に出ないときは **「読者の反応を貼り付けて取り込む」** を実行する）

| Narou.fun の表示 | 統合小説執筆環境の欄 |
|---|---|
| 総合ポイント | `points`（評価） |
| ブクマ | `bookmarks`（ブックマーク） |
| 感想 | `comments`（コメント） |
| レビュー | `reviews`（レビュー） |
| 評価ポイント | `narou_ratingPoints`（評価ポイント） |
| 評価者数 | `narou_raters`（評価者数） |
| 週間読者 | `narou_weeklyReaders`（週間読者） |

**読まないもの**：

- **平均評価**——評価P ÷ 評価者数（10点満点の点の平均）で、なろうのバックアップの「評価平均」（星の平均）と
  尺度が違います。同じ欄へ入れると数字が化けるので読みません（評価Pと評価者数から割れます）
- **評価頻度**——評価者数 ÷ ブクマ で、統合小説執筆環境の**評価率（評価した人数 ÷ 第1話のPV）とは別物**です
- ブクマ×2（総合ポイントのうちブクマ由来の点で、ブクマの数ではありません）
- 日間ポイント・日間ランクイン・最高順位（順位まわり）、形式・文字数・会話率（読者の反応ではない）、あらすじ・題
  （題は 0.13.1 から、集計の見出しに出す作品名としてだけ読みます。統合小説執筆環境へ渡すデータには入れません）
- 「解析」の行き先（**KASASAGI**。なろうの運営会社のアクセス解析）——なろう本体と同じ扱いで、辿りません

**日ごとのブクマと評価ポイントの表（0.7.0から）**：表の数は**その日までの累計**なので、**前の日との差**を
その日の数にします（ブクマ→`bookmarks`、評価P→`narou_ratingPoints`）。

- **ブクマが外された日は、マイナスのまま**統合小説執筆環境へ渡します（そちらのグラフでは0の線より下に赤で出ます）
- **表の最初の日（前の日が無い日）は入れません**。差が取れないためです（翌日以降の取り込みで埋まります）
- 数の後ろの差（`+1`・`±0`）は読みません。累計どうしから自分で取ります（最初の行の「±0」はサイトが置いた値です）
- 日付に年が無いので、**押した日から年を補います**（1月に押した12月の行は前の年）。
  押した日より先の日付の行（リアルタイム表示の「明日」）は入れません
- 7日・14日・全期間の表はどれもページに載っているので、**画面でどれを選んでいても全期間（直近30日）を読みます**（0.14.2。
  0.14.1 までの「表示件数を30に」は要らなくなりました）。日が抜けている表では、抜けた日の翌日も差が取れないので入りません

**記録の日時は、ページの「データ取得」の日付です（0.7.0から。0.14.2 で「最終取得日時」から変わりました）**。
Narou.fun の数は、Narou.fun がなろうから取ってきた時点のものなので、押した時刻ではなくこちらを使います。
ページには日付しか無いので、その日の 0:00（日本時間）として記録します（同じ日のデータを何度渡しても、記録の日時は同じです）。
読めなかったときは押した時刻にし、そうと分かる印をコピーするデータに付けます（統合小説執筆環境の記録のメモに出ます）。

**ほかの方の作品は溜めません**（0.9.0）。Narou.fun は誰の作品のページでも開けるので、この拡張には作者の作品かどうかが
分かりません。そこで、**「覚える」を選んだ Nコードの作品だけ**を、開いたときに溜めます。覚えた一覧は説明のページ
（アイコンを右クリック →「オプション」）で見られ、行を消せば外せます。取り込むときにも、統合小説執筆環境が作品ID（Nコード）で
ご自分の作品かどうかを確かめます（統合小説執筆環境にその作品のNコードを登録していないときは、登録するまで取り込みません）。

**率（離脱率・ブックマーク率・評価率）は、Narou.fun だけでは出ません。** 分母の「第1話のPV」が
Narou.fun に無いためです（KASASAGI にありますが、読みません）。

### その3　公募の一覧を統合小説執筆環境へ渡す（統合小説執筆環境をお使いの方向け。0.12.0）

応募先を選ぶための機能です。読むのは次の3ページだけです。

- ノベルポータルの「文学賞・公募一覧」（`https://creative-story.net/bungakusyou/`）
- ノベルポータルの「投稿サイトのコンテスト一覧」（`https://creative-story.net/202111contest/`）
- ツクリテミライの「小説の公募一覧」（`https://tsukuritemirai.com/kobo/novel/`）

1. **ブラウザ** で上のページを開く。アイコンに **募** が付く
2. アイコンを押す（または、ページの上で右クリックして「公募一覧を取得」）。
   並んでいる公募（名前・締切・賞典・字数・主催・募集作品・応募資格と、公式サイトへのリンク）がクリップボードへ入り、
   VS Code が前に出て、統合小説執筆環境が取り込みます
3. 統合小説執筆環境の「作品目標設定」→「公募の一覧から応募先を選ぶ」で、作品の応募先に入れます
   （いまの字数に合うもの・締切の近いものが上に並びます）

- **ツクリテミライはページごと**（1ページに18件ほど）です。「次へ」で次のページを開いて、もう一度押すと、そのページの分も取り込めます
  （同じ公募は二重になりません）
- **読めた数と読めなかった数を、お知らせで言います。** 1件も読めなかったとき（ページが読み込み終わっていない・ページの作りが変わった）は、
  クリップボードには何も置きません。そのときは、ページの文章を全部選んでコピー（Ctrl+A → Ctrl+C）し、
  統合小説執筆環境の「作品目標設定」→「公募の一覧を貼り付けて取り込む」から入れてください（ヘルパーを使わなくても同じように読めます）
- **初めて開いたときに「開いたときに自動で取得しますか？」とお尋ねします**（0.14.0。ノベルポータルとツクリテミライで1回ずつ）。
  「自動で取得する」と答えると、開いたときに読んで「取得しました（公募 N件）」と出し、ページごとに最新の1つだけこの拡張の中に置きます
  （押したときに画面を読めなかったときに渡すため）。「今までどおり押して取得する」なら、これまでどおり開いただけでは読まず、拡張の中にも残しません
- 説明のページの「統合小説執筆環境へ渡す」を**切っているとき**は、クリップボードへ置くだけで、VS Code は呼びません
  （統合小説執筆環境の「公募の一覧を貼り付けて取り込む」で取り込めます）

### その4　カクヨムの章立てを統合小説執筆環境へ渡す（統合小説執筆環境をお使いの方向け。0.13.0）

カクヨムのバックアップ（ZIP）には、章（大見出し）が入っていません。章は作品管理の画面にだけあるので、そこから読みます
（なろう・アルファポリスはバックアップに章が入っているので、統合小説執筆環境がバックアップのファイルから読みます）。

1. **ブラウザ** でカクヨムの作品管理の画面（`https://kakuyomu.jp/my/works/作品ID`）を開く
2. ページの上で右クリックして「章立てを取得」を選ぶ。**アイコンは押さない**
   （作品管理の画面でアイコンを押すと、これまでどおり読者の反応をまとめて渡します）
3. 話の題と大見出しの並びがクリップボードへ入り、VS Code が前に出ます。統合小説執筆環境が、投稿サイトの設定に登録した
   作品IDで作品を探し（見つからなければ一覧から選びます）、話を題と話数で照らしてから、章立てを見せて確かめます

- 読むのは**話の題と大見出しの字だけ**です。数（PV・応援）はここでは読みません。開いただけでは読みません（0.14.0 の「開いたときの自動取得」の対象にもしていません）。読んだものは、この拡張の中には残しません
- **中見出しは章にしません**（統合小説執筆環境の章は1段だけです）。読まなかった数はお知らせで言います
- 大見出しが1つも見つからないとき（大見出しの無い作品・ページの作りが変わった）は、「見つかりません」と言って何も渡しません
- 統合小説執筆環境の側は、**章立てが既にある作品を上書きしません**（違いを見せて、足りない章だけ足すか・置き換えるかを選びます）。
  話が照らし合わせられなければ、どの話が合わないかを見せて止まります。原稿は書き換えません
- 「統合小説執筆環境へ渡す」を**切っているとき**は、クリップボードへ置くだけです。統合小説執筆環境で作品を右クリックして
  「バックアップから章立て」→「ヘルパーで読んだ章立てから」を選ぶと取り込めます

### クリップボードについて（正直に書きます）

Windows の「クリップボードの履歴」「デバイス間の同期」を有効にしていると、コピーした本文が
Microsoft のクラウドを経由することがあります。これは統合小説執筆環境の「投稿サイト用に変換してコピー」でも同じですが、
未公開のまま取りやめる本文も通りうる、ということは知っておいてください。

## 受け渡しのデータの形

統合小説執筆環境とこの拡張が、クリップボード越しにやりとりする JSON です（`docs/設計書.md` 4章・4.5）。

```json
{
  "novelai-post": 1,
  "site": "kakuyomu",
  "workId": "16816927859000000000",
  "title": "第13話 星の落ちる夜",
  "body": "（変換済みの本文）"
}
```

- `novelai-post` は版。**1でなければ読みません**（知らない版を推測で読むと、欄の意味が変わっていたときに
  本文を取り違えて入れることになるため）
- `site` は `kakuyomu` / `narou` / `alphapolis`
- `workId` は任意。**あれば、投稿画面のURLの作品IDと突き合わせます**（複数作品の取り違え防止）。
  アルファポリスも 0.14.2 から突き合わせます（投稿画面の URL `…/save_episode/{作品ID}` の、数字9桁の作品ID）
- `title` は空でも構いません（空なら、タイトル欄は触りません）
- `body` は50万字まで。それを超えるものは、統合小説執筆環境の側の取り違え（作品まるごと等）とみなして断ります
- `chapter` は任意（0.15.0）。その話が属する章の名前です。アルファポリスでは、同じ名前の章が1つだけあれば選びます。無い・空なら章の欄には触りません（文字列でない・200字を超えるときは、データ全体を断ります）
- **知らない欄は無視して読みます。** 統合小説執筆環境が将来 `caption` などを足しても、古いヘルパーが壊れません

### 読者の反応のデータ（向きが逆。拡張 → 統合小説執筆環境）

こちらは、この拡張が作って**クリップボードへ置く**JSONです（`docs/設計書.md` 4.6）。統合小説執筆環境の
`core/readerStatsEnvelope.ts` が受けます。

```json
{
  "novelai-stats": 1,
  "site": "kakuyomu",
  "workId": "16816927859000000000",
  "title": "（作品名）",
  "readAt": "2026-09-22T01:00:00.000Z",
  "entries": [
    { "scope": "work", "metrics": { "bookmarks": 23, "pv": 1269, "points": 18, "reviews": 6, "likes": 33 } },
    { "scope": "work", "period": "day", "periodKey": "2026-09-22", "metrics": { "pv": 0 } },
    { "scope": "work", "period": "month", "periodKey": "2026-09", "metrics": { "pv": 2 } },
    { "scope": "episode", "episode": 1, "metrics": { "likes": 4, "pv": 102 } }
  ]
}
```

- `readAt` は**読んだ時刻**です（取り込んだ時刻ではありません）。Narou.fun から読んだデータだけは、ページの
  **「データ取得」の日付**（その日の 0:00、日本時間）です（0.7.0から。0.14.1 までは「最終取得日時」。下の `readAtBasis`）
- **`title`（作品名。0.13.3から）**：その画面に出ていた作品の題です。読めたときだけ付き、読めない・100字を超えるときは
  欄ごとありません（途中で切りません）。版の印（`novelai-stats` の `1`）は変えていないので、この欄を知らない
  統合小説執筆環境は読み飛ばして、残りをこれまでどおり受け取ります
- **`tags`（タグ。0.16.0から）**：画面に出ていたタグの並び（文字列の配列。前後の空白を除き、空と重複は除く）。
  カクヨムは作品管理の画面のタグ、なろうファンDB は作品ページのキーワードです。タグの欄があって0個なら `[]`、
  その画面にタグの欄が無い・読めないときは欄ごとありません（アクセス数の画面には付きません）
- **`completion`（連載の状態。0.16.0から）**：`"ongoing"`（連載中）か `"completed"`（完結）。画面の字で決め、
  読めない・どちらでもない（なろうの短編など）ときは欄ごとありません
- **`ownedVia`（その作品を覚えた理由。0.16.0から）**：束にするときに付けます。本人しか開けない画面（カクヨムの作品管理）で
  覚えた作品は `"owner-page"`、「覚える」と答えた・説明のページで書いた作品は `"approved"` です。
  `"approved"` の作品も、本人しか開けない画面（カクヨムの作品管理、アルファポリスのマイページ）を開くと `"owner-page"` になります（0.17.1）
- `tags`・`completion`・`ownedVia` は省いてよい欄なので、版の印は `1` のままです
- **アルファポリス（0.17.0から）**：`site` は `"alphapolis"`（`source` は付きません）。お気に入り数→`bookmarks`、累計ポイント→`points`、
  話ごとのいいね→`likes`。ほかの数は `alphapolis_` で始まる名前です（24時間のポイント `alphapolis_points24h`・累計の順位 `alphapolis_rankTotal`・
  24時間の順位 `alphapolis_rank24h`・ハート `alphapolis_hearts`・話ごとのしおり `alphapolis_bookmarks`・エール `alphapolis_yells`・誤字報告 `alphapolis_typoReports`）。
  作品管理の一覧からは作品ごとに1件ずつ作ります。作品の設定の画面のタグと連載の状態は、同じ作品の数の件に載せて渡します
- `workId` はURLから読んだ作品IDです。統合小説執筆環境はこれを作品ごとの記録と突き合わせ、**別の作品の画面を開いたまま
  押したとき**に取り込みを止めます
- カクヨムの表示を統合小説執筆環境の欄へ写す対応は、フォロワー→`bookmarks`、PV→`pv`、★の数→`points`、
  レビュー→`reviews`、応援→`likes`、応援コメント→`comments` です
- **「読者からの反応」の6欄（フォロワー・PV・★・レビュー・応援・コメント）は、数字にマウスを
  当てたときに出る正確な数から読みます**（0.2.1から）。画面の表示が `1.05M`・`27.5K` のように
  省略されていても、`1,053,339`・`27,534` が入ります。正確な数がどこにも無いときは、その欄を入れません
- **今週は読みません。** 統合小説執筆環境の記録の粒度は日・月・年・累計で、週がありません。無い粒度を
  月や日に寄せると、あとから見て何の数字か分からなくなります
- 読めなかった欄は入れません（`0` を書きません）
- **`source`（どこで読んだか。0.6.0から）**：Narou.fun の作品ページから読んだデータだけに
  `"source": "narou.fun"` が付き、`site` は `"narou"`、`workId` は URL の Nコードです。
  **`source` の無いデータは「そのサイトの管理画面そのもの」**の意味で、カクヨムのデータは 0.5.0 までと同じ形です。
  統合小説執筆環境は、なろう本体のデータ（`source` 無しの `"narou"`）を断り続け、Narou.fun のデータだけを受けます。
  この欄を知らない古い統合小説執筆環境は、Narou.fun のデータを「なろうだから」と断ります（取り込みはされません）
- **`readAtBasis`（記録の日時が何の日時か。0.7.0から）**：Narou.fun のデータだけに付きます。
  `"fetched"` はページの「データ取得」の日付（0.14.1 までは最終取得日時）を読めた、`"clicked"` は読めずに押した時刻へ落とした、の意味です。
  この欄の無いデータ（カクヨム）は、これまでどおり押した時刻です
- **日ごとの増減の行（0.7.0から）**：Narou.fun の日ごとの表から作る `period: "day"` の行は、
  `bookmarks`・`narou_ratingPoints` が**マイナスのこともあります**（前の日より減った日）。
  統合小説執筆環境がマイナスを受けるのは、この2つの欄の日ごとの行だけです

### 溜めた分をまとめたデータ（束。0.9.0）

「まとめて渡す」でクリップボードへ置くのは、上の読者の反応のデータを**配列で束ねたもの**です。
統合小説執筆環境の取り込み口（`vscode://nonahisa.novel-ai-assistant/import-reader-stats`）が受けます。

```json
{
  "kind": "novelai-stats-bundle",
  "version": 1,
  "handedAt": "2026-09-23T05:10:00.000Z",
  "items": [
    { "novelai-stats": 1, "site": "kakuyomu", "workId": "16816927859000000000", "readAt": "…", "entries": [ … ] },
    { "novelai-stats": 1, "site": "narou", "source": "narou.fun", "workId": "N1234AB", "readAt": "…", "readAtBasis": "fetched", "entries": [ … ] }
  ]
}
```

| 欄 | 型 | 意味 |
|---|---|---|
| `kind` | 文字列 | いつも `"novelai-stats-bundle"`（束の目印） |
| `version` | 数 | いつも `1`（束の版。1でなければ読まない取り決め） |
| `handedAt` | 文字列（ISO 8601、UTC） | まとめて渡した時刻 |
| `items` | 配列 | 上の「読者の反応のデータ」（`novelai-stats` v1）そのものを、**溜めた順**（古いものが先）に並べたもの。1件は「1つの作品の1つの画面（アクセス数ならそのページ）」。ランキングの順位だけを渡すときは空の配列 |
| `rankings` | 配列（省いてよい） | 0.19.0。ランキングの画面で読んだ、覚えた作品の順位（下）。読んだ順。順位が無ければ欄ごとありません。**`items` も `rankings` も空の束は作りません** |

`rankings` の1件（受け手との取り決め。2026-11-02）：

```json
{ "site": "kakuyomu", "workId": "16816927859000000000", "title": "架空の題",
  "board": "rankings/fantasy/weekly/long", "boardLabel": "週間異世界ファンタジーの長編ランキング",
  "span": "weekly", "genre": "異世界ファンタジー", "rank": 12, "date": "2026-11-02", "readAt": "2026-11-02T12:03:00.000Z" }
```

| 欄 | 意味 |
|---|---|
| `site` | `"kakuyomu"` か `"alphapolis"`（なろうは入りません） |
| `workId` | 覚えた作品の作品ID |
| `title` | 画面に出ていた作品名（省いてよい。照合には使わない） |
| `board` | 一覧の区分の鍵。カクヨムは `rankings/{ジャンル}/{期間}/{long・short・all}`（ページ番号は入れない）、アルファポリスは `novel/ranking/{hot・annual・completed}`（大分けの `?category=` があれば足す） |
| `boardLabel` | 画面の見出し（「日間総合の長編ランキング」「HOTランキング」）。読めなければ URL から組んだ名前 |
| `span` | `daily`・`weekly`・`monthly`・`yearly`・`total`（カクヨムの累計）・`24h`（アルファポリスの HOT）・`other`（完結など） |
| `genre` | ジャンルの名前（省いてよい。総合は省く） |
| `rank` | 順位（1以上） |
| `date` | その順位を読んだ日（日本時間の日付） |
| `readAt` | 読んだ時刻（ISO 8601、UTC） |

- 同じ順位の見分けは `site`＋`workId`＋`board`＋`date`。同じ鍵を2度読んだら、後のほうで置き換えます
- 一覧に載っていない作品の件（圏外）は作りません（2ページ目や別の区分に載っているかもしれないため）

- `items` の1件ずつの形は 0.8.0 までと**まったく同じ**です。溜めるための印（どの画面か・いつ溜めたか）は束に入れません
- 同じ作品の作品管理とアクセス数が両方入ることがあります（話ごとの数が重なります）。統合小説執筆環境の取り込みは
  追記（同じ話の同じ数字は上書き）なので、1件ずつ順に取り込めば二重になりません

### 公募の一覧のデータ（0.12.0。拡張 → 統合小説執筆環境）

公募の一覧のページで押したときに、この拡張が作って**クリップボードへ置く**JSONです。統合小説執筆環境の
`core/contestListing.ts` が受けます（取り込み口は `vscode://nonahisa.novel-ai-assistant/import-contests`）。

```json
{
  "novelai-contests": 1,
  "source": "novelportal",
  "pageUrl": "https://creative-story.net/bungakusyou/",
  "readAt": "2026-09-23T10:00:00.000+09:00",
  "items": [
    { "name": "第3回 みずうみ文学賞", "url": "https://example.com/…", "section": "2026年10月締切", "text": "第3回 みずうみ文学賞\n締切：2026年10月31日（土）\n字数：…" }
  ]
}
```

| 欄 | 意味 |
|---|---|
| `novelai-contests` | 版。いつも `1`（1でなければ読まない取り決め） |
| `source` | `novelportal`（ノベルポータル）か `tsukuritemirai`（ツクリテミライ） |
| `pageUrl` | 読んだ一覧のページ（`#` から後ろは落とす） |
| `readAt` | 読んだ日時（その土地の時差つき。統合小説執筆環境が「○月○日時点の情報」と出すため） |
| `items` | 1件ずつの公募。`name` は名前、`url` は公式サイトへのリンク（ツクリテミライは、そのサイトの公募の詳しいページ。http・https だけ）、`section` は一覧の中の見出し（ツクリテミライは無し）、`text` は1件の枠の文（4,000字まで） |

- **1件の中身（締切・字数…）の読み分けは、この拡張ではしません。** 統合小説執筆環境が、ページの文を貼り付けたときと
  同じ読み取りで読みます（2か所で読むと、片方を直した日に食い違うため）
- ノベルポータルの「開催予定」の表は、公募として入れません

### 章立てのデータ（0.13.0。拡張 → 統合小説執筆環境）

カクヨムの作品管理の画面で「章立てを取得」を選んだときに、この拡張が作って**クリップボードへ置く**JSONです。
統合小説執筆環境の `core/chapterEnvelope.ts` が受けます（取り込み口は `vscode://nonahisa.novel-ai-assistant/import-chapters`）。

```json
{
  "novelai-chapters": 1,
  "site": "kakuyomu",
  "workId": "1177354054000000000",
  "pageUrl": "https://kakuyomu.jp/my/works/1177354054000000000",
  "readAt": "2026-09-24T09:00:00.000+09:00",
  "episodes": [
    { "heading": "プロローグ", "part": null },
    { "heading": "１話　潮の匂い", "part": "第一章『岬』" }
  ]
}
```

| 欄 | 意味 |
|---|---|
| `novelai-chapters` | 版。いつも `1`（1でなければ読まない取り決め） |
| `site` | いまは `kakuyomu` だけ |
| `workId` | 作品ID（作品管理の画面のURLの数字）。統合小説執筆環境が、どの作品のものかを探すのに使う |
| `pageUrl` | 読んだ画面（`?` と `#` から後ろは落とす） |
| `readAt` | 読んだ日時（その土地の時差つき） |
| `episodes` | 画面に並んだ順の話。`heading` は話の題そのまま（200字まで）、`part` はその話が属する大見出し（大見出しより前の話は `null`） |

- **話数の読み分け（「１話　潮の匂い」→ 1話）は、この拡張ではしません。** 統合小説執筆環境が、バックアップの話と同じ読み方で読みます

### 溜まりの上限と消し方（0.9.0）

- **上限は 50画面・200万字**（データの文字数の合計）。越えたら、**前に溜めたものから**消えます
- 同じ画面（同じ作品・同じ種類の画面・アクセス数なら同じページ）を開き直すと、**新しいほうで置き換わります**
- **渡すと溜まりは空になります。** 渡した分は「控え」として、**次に渡すまで（長くても7日）** 残ります。
  統合小説執筆環境が受け取れたかはこの拡張には分からない（通信しないので返事が来ない）ため、説明のページの
  **「もう一度渡す」** で同じものを渡し直せます
- 説明のページの **「溜まりを空にする」** で、渡さずに消せます。覚えた作品は、説明のページの欄から行を消して保存すると外れます
- 保存しているのは、溜まり・控え・覚えた作品（サイト・作品ID・覚えた日）・訊きかけの作品の4つと、
  0.10.0 からの集計のための記録（下）、0.11.0 からの「統合小説執筆環境へ渡す」の入・切（保存の鍵 `helperSettings`）だけです
- 「統合小説執筆環境へ渡す」を切っている間は、溜まりに溜めません。切る前に溜まっていた分は、そのまま残ります
- **ランキングの順位（0.19.0）は、溜まりの中に別に300件まで**持ちます（同じ作品・同じ区分・同じ日は置き換え。越えたら古いものから消えます）。
  渡すと控えへ移り、「もう一度渡す」にも入ります。「溜まりを空にする」で一緒に消えます。アイコンの「読3」の数には入りません
- **お祝いの記憶（0.19.0。保存の鍵 `rankingMemory`）**：お祝いした印と、一覧の区分ごとに前に見た順位を、それぞれ300件まで持ちます。
  同じ日の同じ順位で二度お祝いしないためと、演出の大きさを決めるためだけに使います。「溜まりを空にする」では消えません

### 記録の上限と消し方（0.10.0）

集計のための記録は、溜まりとは**別のもの**です（保存の鍵も別の `readerHistory`）。**統合小説執筆環境へ渡しても、
溜まりを空にしても消えません。**

- **覚えた作品だけ**を記録します。説明のページで覚えた作品から外すと、その作品の記録も消えます
  （外したのは、ご自分の作品ではなかったからかもしれないため）
- **同じ作品・同じ日の分は1つにまとめ、欄ごとに新しい数で置き換えます**（開き直すたびに増えません）。
  作品管理とアクセス数のように読める欄が違う画面は、欄ごとに合わさります。古い読み取りで新しい数を上書きしません
- 話ごとの数は、日ごとには残さず、**話ごとにいちばん新しい数だけ**を持ちます（率に要るのはそれだけで、
  219話の作品を日ごとに残すと、半年で作品1つが保存の持ち分を食い尽くすため）
- **上限は 20作品・180日（月ごとの数は24か月）・150万字**（記録全体の文字数）。越えたら、
  作品はいちばん長く記録していないものから、日はいちばん古い日から消えます（どの作品も最後の1日は残します）
- 作品名（0.13.1）も記録と一緒に置きます。**作品ごとにいちばん新しい1つだけ**で、作品名を変えたら、次に画面を開いたときに新しい名前になります
- 説明のページの **「集計の記録を消す」** で、全部消せます（覚えた作品と溜まりは残ります。作品名も消えますが、その作品の画面をもう一度開くと戻ります）

## 各サイトの規約について（要旨）

2026-09-05に各サイトの利用規約の原文を確かめた結果です（`docs/設計書.md` 3章が正、ここは要旨）。

| サイト | 判定 |
|---|---|
| **カクヨム** | 自動化・収集を禁じる条文がなく、負荷も妨害も生まない貼り込みは**問題なし**。第1弾で対応 |
| **アルファポリス** | 同じく明示条文なし。**問題なし**。第1弾で対応 |
| **小説家になろう** | 第14条23号が「APIを使う以外の**自動化された手段でのアクセス・データ収集**」を禁止。
貼り込み（欄を埋めるだけ）は文言上その対象外と読めますが、**4サイトで最も厳しい書きぶり**で、
**送信の自動化は明確に禁止の対象です**。表に枠だけ置き、**貼り込みは行いません**。
読み取り（アクセス解析の取り込み）は**対応しない**と決めています。
**なろうの数は、分析サイト Narou.fun のご自分の作品のページから読みます**（0.6.0。別のサイトで、
robots.txt は全許可・サイト自身に「クリップボードにコピー」の釦があります。利用規約の頁は見つかっていません） |

この拡張が「自動化されたアクセス」に当たらないと考える理由は、**サーバーへ何も送らない**からです。
ページを開くのも、投稿ボタンを押すのも、作者本人の操作です。

（写しを作らないため）。ビルド工程はありません——読み込んで、そのまま動きます。

### テスト

```powershell
npm install
npm test
```

しないことを見張るテスト（`test/redLine.test.js`）は、プログラムの中身を調べて「通信のコードが無いこと」「送信のコードが無いこと」
「Cookie に触れていないこと」「文字列からコードを作っていないこと」「HTMLを組み立てて差し込んで
いないこと」「ページへ要素を差し込んでいないこと」「ページへコードを注入していないこと」「ページと窓越しにやり取りしていないこと」
「新しいタブや窓を開いていないこと」「VS Code を呼ぶ場所が1つで、リンクにデータを載せていないこと」
「権限が増えていないこと」を毎回確かめます。裏方（service worker）と、そこから読み込むファイルも調べる対象です。

0.2.0 で読み取りを足したので、「ページから集めない」の見張りも足しました——**コピーするデータを組み立てるのは
`content/read.js` だけ**（0.9.0 から、束で包む `common/stash.js` も）／**ページの文字を読むのは `content/read.js`（数を読む部分）と `content/fill.js`（欄を埋める部分）だけ**／**読んだものの
行き先は、拡張の中の溜まりとクリップボードだけ**（0.9.0。溜めるのは `chrome.storage.local` だけで、触るのは裏方だけ。sync・ページの保存は使わない）／**ページを見張らない**。
ここに3つ目のファイルが増えたら、それは「しないこと」そのものを変えることになります（ついでに足してよいものではありません）。
**0.12.0 で、作者の依頼により3つ目（`content/contestRead.js`、公募の一覧）を足しました。** 入るのは公募の一覧の3ページだけで、
読んだものは押したときのクリップボードだけへ行きます（溜めない）。テストはこのファイルを名指しで許し、公募の一覧のデータ
（`novelai-contests`）を組み立てるのもこのファイルだけ、入る範囲もその3ページだけ、を見張ります。

`test/contestRead.test.js` も、統合小説執筆環境のプログラム一式が隣にあるときだけ、**統合小説執筆環境の、公募の一覧を受け取る
本物の部分**（`core/contestListing.ts`）にこのデータを読ませて確かめます（0.12.0）。

`test/history.test.js` も同じように、統合小説執筆環境のプログラム一式が隣にあるときだけ、**同じ読者の反応を
統合小説執筆環境の率の計算（`core/readerRates.ts`）にも通して**、この拡張の集計の率（式・値・材料が欠けたときの理由）が
一致することを確かめます（0.10.0。式を写しで持っているので、片方だけが変わった日に気づくため）。

`test/readEnvelope.test.js` は、統合小説執筆環境のプログラム一式（`novel-ai-assistant`）がこのフォルダーの隣にあるときだけ、
**統合小説執筆環境の、データを受け取る本物の部分**（`core/readerStatsEnvelope.ts`）に、このデータを実際に読ませて確かめます。
このデータの形は2つの拡張の間の取り決めなので、確かめ方を写すのではなく、相手に直接読ませています
（統合小説執筆環境のプログラムが無い環境では、そのテストだけ飛ばします）。

調べるファイルは**その場でフォルダーを辿って集めます**（`node_modules`・`test`・`.git` 以外の
すべて）。手で書いた一覧にすると、新しく足したファイルが検査されないまま通ってしまうためです。
**調べる仕組みそのものが働いているか**——新しいファイルを拾うか、禁止の書き方を本当に見つけられるか——も、
架空のプログラムを読ませて同時に確かめています。
